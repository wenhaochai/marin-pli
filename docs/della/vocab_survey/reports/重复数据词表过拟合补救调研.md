# 把稀有行之外的代价也拿下：下一批实验清单

调研日期：2026-10-21。范围：本项目全部实验记录、kexue.fm 本地库、网络上的论文。

**结论先行。** 按 2026-10-21 的目标，每种 tokenizer 的 8 遍结果要等于它自己的不重复结果。现在只有 256 字节词表接近目标，差距是 0.0041 bpb。128K 的最好结果只关掉约 1/3 的差距，剩 0.053 bpb。64K、32K、16K 还没有任何补救实验。8K 只试过 rs，差距从 0.023 降到 0.019。项目已经找到两个能叠加的手段。第一个手段处理稀有输入行（cvd、detach），约降 0.018。第二个手段在每一遍换数据顺序（rs），约降 0.008。128K 剩下的代价主要在稀有目标 token 上。到现在为止，每一个改输出头的做法都失败了。文献和 kexue.fm 中没有任何方法在 8 遍、约 2.5 个不重复 token/参数的设置下被验证能完全追平不重复数据。因此，下一批实验应该分三条线：(1) 把已经有效的 cvd fp2 + rs 移植到 64K/32K/16K，这一步关掉的总差距最多；(2) 先用只需评测的诊断找出 128K 剩余代价在哪里（覆盖缺失、稀有目标、主干）；(3) 再测几个零额外算力、直接针对稀有目标或"方向记忆"的新做法：只切分稀有 token 的重分词、按频率分级的替换率、Lazy Adam、向片段均值衰减。集成、蒸馏、扩散目标、MIR、FGM 都要多倍算力，不符合"同算力"规则。

标记说明：
1. 【推断】表示调研者的推理，没有实验或文献直接支持。
2. 【未验证计算】表示调研者自己的数值计算，没有人复核，也没有实验验证。
3. 【分歧】表示来源之间有冲突。

## 1. 每种 tokenizer 离目标还差 0.004 到 0.080 bpb

目标线 = 同一 tokenizer、同算力、不重复 token 的 Paloma macro bpb（已完成种子的均值）。差距 = 8 遍结果减目标线。

| tokenizer | 目标线（不重复） | 不改动的 8 遍 | 差距 | 最好的补救 | 最好补救的差距 | 状态 |
|---|---|---|---|---|---|---|
| 128K | 1.3856（2 种子） | 1.4653 | 0.0797 | detach + rs 1.4389（2 种子） | 0.0533 | 关掉约 33% |
| 64K | 1.3912（1 种子） | 1.4659 | 0.0747 | 无 | 0.0747 | rs 排队中（15961318） |
| 32K | 1.4020（1 种子） | 1.4609 | 0.0589 | 无 | 0.0589 | rs 排队中（15961318） |
| 16K | 1.4229（1 种子） | 1.4665 | 0.0436 | 无 | 0.0436 | rs 排队中（15961377） |
| 8K | 1.4539（2 种子） | 1.4769 | 0.0230 | rs 1.4730（1 种子） | 0.0191 | 关掉约 17% |
| 256 字节 | 1.3695（1 种子） | 1.3736 | 0.0041 | 无 | 0.0041 | 种子 1（15832611）与 rs（15883244）运行中 |

来源：[figs] fig-progress、[doc] Q11。

各 tokenizer 的状态：
1. **128K。** 不改动时差距 0.0797。最好的两个结果是 detach + rs 1.4389（2 种子，差距 0.0533）和 cvd + rs 1.4397（3 种子，差距 0.0541）。这两个结果的不重复点也被改动了（cvd 不重复 1.3916，比 128K 高 0.006）。不重复点保持原样的最好结果是 cvd fp2 + rs 1.4412（2 种子，差距 0.0556）。cvd 的 seed-1 配对中，最稀有输入十分位的代价从 0.219 降到 0.126，最稀有目标十分位的代价只从 0.210 降到 0.179（[doc] Q10i B1）。所以剩下的代价主要在稀有目标上。
2. **64K。** 差距 0.0747，几乎等于 128K。它的 8 遍结果（1.4659）和 128K（1.4651）几乎一样，所以差距主要来自它自己的重复代价【推断】。没有补救实验，没有第二个种子，没有分十分位分析。
3. **32K。** 差距 0.0589。8 遍结果 1.4609 是 BPE 词表中最低，但只有 1 个种子，页面也说这个微小优势没有复现（[doc] Q7）。
4. **16K。** 差距 0.0436。情况同 32K。
5. **8K。** 差距 0.0230。rs 只有 1 个种子，结果 1.4730，差距 0.0191。8K 的分十分位代价是平的（最稀有输入十分位 0.033，其他 0.015–0.036；最稀有目标十分位 0.002），所以 8K 的代价不集中在稀有行上（[figs] fig-freq-in、fig-freq-out）。这一点决定 8K 需要通用手段，而不是 cvd 类手段【推断】。
6. **256 字节。** 差距 0.0041，小于 tokenizer 之间的种子差（约 0.005–0.006）。2.4 遍时代价为 −0.0024。种子 1 和 bytes + rs 正在运行。

种子噪声：128K 两个种子的不重复结果差 0.0056（1.3828 与 1.3884）；同一设置的另一次 128K s1 不重复运行结果 1.3822，与重跑差 0.006（[doc] Q10f）。项目用 0.012 作"超出种子噪声"的阈值。

**"能否完全追平"的估计。** 一位调研者用 Muennighoff 2023 的重复数据公式（R* ≈ 15.4）和 Chinchilla 常数估算：8 遍的不可避免代价约 0.04 nats/token，约 0.013 bpb（按 4.3 字节/token）([Muennighoff et al. 2023](https://arxiv.org/html/2305.16264))。这是【未验证计算】，常数是借来的。另外两点削弱它：
1. 字节词表的实测代价是 0.004，低于这个"下限"。按每 token 1 字节换算，这个公式给字节的下限会更高。所以这个公式不能在不同 tokenizer 之间通用【推断】。
2. 更极端设置下的重新拟合给出 AR 模型的 R* ≈ 31–32，不是 15 ([Prabhudesai et al. 2025](https://arxiv.org/html/2507.15857))。R* 越大，下限越低。

结论：字节词表证明这个模型和算力可以在 8 遍下几乎不损失。128K 是否能完全追平没有证据。现实的中期目标是把 128K 的差距降到 8K 的水平（约 0.02）。

## 2. 项目已经确定的事实：哪些有效、哪些失败、机制在哪里

### 2.1 有效的做法（300m 128K，除非另有说明）

1. **cvd（随机替换稀有输入行）。** 训练时，id 在 [8000, V−257) 的位置以 0.5 的概率把输入行换成它的 8K 片段行的均值。评测用自己的行。3 种子均值：不重复 1.3916，8 遍 1.4474，领先 128K 0.018，每个种子都超过阈值（[doc] Q10e、[tv] L329–416）。
2. **rs（每一遍换顺序）。** 第 2–8 遍用新的随机顺序读同一批 4096-token 窗口。128K −0.008，8K −0.004（各 1 种子）。cvd + rs 3 种子均值 1.4397，比 cvd 再降 0.008，两者可以叠加（[doc] Q10、Q10e）。
3. **detach（片段均值不回传梯度）。** 与 cvd 持平：3 种子 8 遍均值 1.4441。detach + rs 2 种子均值 1.4389（[doc] Q10i、Q10j）。
4. **cvd 从第 2 遍开始（cvd fp2）。** 8 遍 1.4471，领先与 cvd 相同（0.018），不重复点就是 128K 本身。cvd fp2 + rs 1.4412（[doc] Q10h、Q10l）。detach 从第 2 遍开始会失去部分收益（1.4524）（[doc] Q10j）。
5. **grad 消融（在抽中的位置只挡住自身行的梯度）。** 不重复 1.3856（与 128K 一样），8 遍 1.4525，保留 cvd 领先的 0.013（1 种子）（[doc] Q10i）。**这说明：减少稀有行从重复上下文接收的梯度次数，就能拿到大部分收益，而且不损失不重复拟合。**
6. **cvd32k（只替换 id ≥ 32000，用 32K 片段）。** 不重复与 128K 只差 0.001，8 遍比 128K 低 0.014（1 种子）。"最稀有的 token 贡献了大部分收益"（[doc] Q10h）。
7. **bpd0.1（第 2–8 遍每遍新的 BPE-dropout 切分）。** 2 种子领先 0.0117，略低于阈值；叠加在 cvd 上只降 0.003（[doc] Q10f、Q10g）。
8. **520m。** cvd 2 种子领先 0.021–0.023；detach + rs 1.3627（1 种子），是 520m 最低的 8 遍结果（[doc] Q10h、Q10k）。

### 2.2 失败的做法

1. **冻结或减慢稀有输出行。** fop8kb（第 2 遍起冻结稀有输出行）：不重复 1.4776，8 遍 1.5292，两者都远差于 128K。G（稀有输出行速率 0.1×）：1.4080 / 1.4870，8 遍比 128K 更差。L（cvr + 稀有输出行减慢）：1.4249 / 1.4871（[doc] Q5b、Q10c、Q10e）。
2. **输出头组合。** cvout 均值头：不重复 1.7670（旧指标），均值把 token 的 logit 限制在最好片段之下。cvout 求和、fo8k（稀有输出行固定在初始值）：门控失败，取消（[doc] Q5、Q5b）。K（输出头也组合 + 残差）：1.4243 / 1.4818（[doc] Q10e）。
3. **停止在稀有目标上训练。** rm8kp5 从第 5 遍起屏蔽稀有目标：8 遍崩到 2.845；加冻结 2.095；移出 softmax 1.633（[doc] Q10）。
4. **cvin（训练和评测都用片段均值）、cvr（片段均值 + 残差）。** 代价下降，但不重复拟合变差，8 遍与 128K 大致持平；cvr 3 种子领先 0.008，低于阈值（[doc] Q4、Q10）。
5. **unk（抽中位置换成一个共享可学行）。** 不重复差 0.018，8 遍高于 128K（[doc] Q10i）。
6. **cvd p0.8。** 更多替换只损失不重复拟合，8 遍不变（[doc] Q10h）。
7. **fip（第 2 遍起冻结稀有输入行，两种 run 都冻结）。** 领先 0.009–0.010，低于阈值；不重复损失 0.013（[doc] Q4c）。
8. **探针：更短窗口（3072）、更多步（batch 96，1.33× 步数）。** 代价都不变（[figs] fig-window、fig-steps）。
9. **低秩表（rank 48）。** 拟合比 8K 还差，无结论（[doc] Q9）。
10. **早先的 Over-Tokenized n-gram 输入表。** 重复数据下反转：2.4 遍时比基线差 0.153（项目记忆 `project_ss_ov_kaiyue_baseline`）。

### 2.3 已确定的机制

1. **代价随词表单调变化。** 300m 8 遍代价：128K 0.0823 → 64K 0.0747 → 32K 0.0589 → 16K 0.0436 → 8K 0.0262 → 字节 0.0041（种子 0）。2.4 遍时所有 tokenizer 的代价 ≤ 0.016，没有词表趋势（[figs] fig-vocab-final）。
2. **128K 的代价集中在最稀有的十分位。** 输入侧 0.219，目标侧 0.210；8K 和字节是平的（[figs] fig-freq-in、fig-freq-out）。
3. **记忆在稀有行的方向上，不在范数上。** 重复不增加稀有输入行的范数（计数 1–9：1.607 与 1.628）；重复让稀有行偏离它的片段均值（128K 计数十分位 4–7 的余弦 0.067→0.032 到 0.198→0.166），cvd 抵消这一偏离（[doc] Q10i B3、Q10n、[rn]）。
4. **剩余代价不经过稀有输出行。** K 和 L 实验的结论是"cvr 留下的代价不能通过稀有输出行去掉"（[doc] Q10e）。【推断】这意味着稀有目标的代价主要存在于主干：主干学会从被记住的上下文预测稀有 token。
5. **代价不随上下文长度增长。** 128K 在 32 字节处 0.090，在 23 KB 处 0.076（[figs] fig-pos）。
6. **本配方几乎没有显式正则。** 线性层用 MuonH，每次更新后把矩阵的 Frobenius 范数精确恢复；lm_head 用 AdamH，也保持范数；输入 Embedding 用普通 Adam（`scale_by_adam`），没有任何权重衰减项，虽然启动脚本传入 weight_decay=0.1（[mh]、[doc] Q10n）。
7. **优化器超参（300m）。** lr 0.01，adam_lr 0.002，β1 0.9，β2 0.98，eps 1e-15，momentum 0.98，cosine，warmup 1000，batch 128 × 4096，11444 步（[scal] L388、L662–680）。
8. **不改动的 8 遍 run 每一遍用完全相同的顺序。** rs 只改变 4096-token 窗口的顺序，不改变窗口边界（[mat] 文档字符串）。**每一遍重新打包文档（新窗口边界）还没有测过。**
9. **8 遍子集中从未出现的 token 类型，输入行停在初始值附近。** 前 2 亿 token 中计数为 0 的行：不重复 run 范数 0.522，8 遍 run 0.037（[rn]）。

## 3. 下一批实验的排序清单

排序依据：(a) 能关掉多少目标差距（跨所有 tokenizer 合计）；(b) 是否直接针对 §2.3 中已确定的机制；(c) 额外算力；(d) 失败风险。

成本单位：300m BPE 的一次 8 遍 run 约用 4 张 H100、≤ 9 h，即约 30–36 H100·h（按已排队任务的时限推算，[yaml] L187–192）。字节 run 约 19 h × 4 张 = 约 76 H100·h。

"需要配对的不重复 run 吗？"的规则：
1. 只在第 2–8 遍生效的改动：对目标来说不需要，因为不重复点就是不改动的 tokenizer。
2. 从第 0 步生效的改动：需要，因为它也可能改变不重复结果。
3. 可能也会改善不重复训练的改动（学习率、EMA、权重衰减）：若要声称"这是对重复的补救"，就需要配对 run。

### 总表

| 排名 | 想法 | 针对的机制 | 额外算力 | 需要配对不重复 run |
|---|---|---|---|---|
| 1 | cvd fp2 + rs 移植到 64K/32K/16K | 稀有输入行 | 0 | 不需要 |
| 2 | 只评测的诊断：分十分位、覆盖缺失、按计数门控的组合行 | 稀有输入行 + 覆盖 | 只评测 | 用不重复检查点做对照 |
| 3 | 只切分稀有 token 的每遍重分词（输入 + 目标） | 稀有目标 | 0（换缓存） | 不需要 |
| 4 | 按频率分级的 cvd 替换率 | 稀有输入行 | 0 | 不需要（fp2 版） |
| 5 | 每遍重新打包文档（新窗口边界） | 通用（数据顺序） | 0（换缓存） | 不需要 |
| 6 | Lazy Adam（只用于输入 Embedding） | 稀有输入行 | 0 | fp2 版不需要 |
| 7 | 向片段均值衰减（decay-to-composition） | 稀有输入行的方向 | 约 0 | 从第 0 步版本需要 |
| 8 | 稀有目标位置的输出行梯度 dropout | 稀有目标（输出行） | 约 0 | 不需要 |

### 排名 1：把 cvd fp2 + rs 移植到 64K、32K、16K

1. **想法。** 对 64K、32K、16K，从第 2 遍起，以 0.5 的概率把 id ≥ 8000 的输入行换成它的 8K 片段行的均值（梯度进入片段），同时用 rs 缓存。8K 另做一个探针：用 2K（或 1K）截断的片段。
2. **来源。** 项目自己的结果（[doc] Q10h、Q10l）。先例：AWD-LSTM 的词级 Embedding dropout ([Merity et al. 2017, arXiv 1708.02182](https://arxiv.org/abs/1708.02182))；用已有 token 的组合初始化新 token 的行 ([FOCUS, arXiv 2305.14481](https://arxiv.org/abs/2305.14481))。
3. **为什么针对本项目的机制。** 稀有输入行的方向记忆是已确定的机制。64K 的代价（0.0747）几乎等于 128K，所以 64K 应该有相同的稀有行峰值【推断】。32K、16K 的稀有行更少，收益应该更小【推断】。8K 的十分位代价是平的，所以预测 8K 几乎不受益【推断】。
4. **在本栈上的实现。**
   1. 去掉 [scal] L378 对 `VOCAB_K` 的限制（cvd 现在只允许 128K）。
   2. 截断词表是 128K 的前缀截断，[tv] L9 把"稀有"定义为 id K..V−257。所以 64K 的 id 应该与 128K 的 id < 64000 一致。需要先核对这一点。若一致，把 `tokenizers/marin-small/v8/expand_full.npz` 限制到 id < K 就是映射表。
   3. 8K 探针要新建 v2k 的 `expand_full.npz`，用建 v8k/v32k 时的同一工具。
   4. 输入 Embedding 仍用普通 Adam；片段行接收梯度（cvd 模式），因为 detach fp2 会失去部分收益。
5. **成本。** 3 个 tokenizer × 1 个 8 遍 run ≈ 90–110 H100·h；加第 2 个种子则加倍。8K 探针再加约 35 H100·h。
6. **预期效果与风险。** 【推断】64K：比 rs 单独多降 0.015–0.02，组合后差距约 0.05；32K：约 0.01；16K：约 0.005–0.01；8K：≈ 0。风险：截断词表的 id 对齐若不成立，需要重建映射；32K/16K 中 id ≥ 8000 的比例较小，收益可能低于噪声。
7. **配对不重复 run。** 对目标不需要（fp2）。

### 排名 2：只需评测的诊断，以及按计数门控的组合行

1. **想法。**
   1. 对 64K/32K/16K 的已有不重复与 8 遍配对、8K + rs、cvd + rs、detach，计算按训练频率分十分位的输入侧和目标侧代价。
   2. 把最稀有十分位再拆成三组：8 遍子集中计数为 0、计数 1–7、计数 ≥ 8 的 token 类型。
   3. 在 cvd、detach、cvd fp2 + rs 的最终 8 遍检查点上评测一个新规则：子集计数 < c 的 token 用片段均值行作输入，其他用自己的行；c ∈ {1, 8, 64}。
2. **来源。** 稀有或未训练的 token 行停在退化状态，可以从权重中检测出来 ([Land & Bartolo 2024, arXiv 2405.05417](https://arxiv.org/abs/2405.05417))。最常被记住的数据点含有极稀有 token ([Morris et al. 2025, arXiv 2505.24832](https://arxiv.org/abs/2505.24832))。
3. **为什么针对本项目的机制。** 8 遍 run 中计数为 0 的输入行停在初始值附近（范数 0.037，不重复 run 0.522，[rn]）。评测文本中这些类型一出现，模型就读到一个未训练的行。这一部分不是"记忆"，而是覆盖缺失，而且它随词表增大【推断】。cvd 模型训练时已经习惯把片段均值当作输入，所以评测时替换未训练的行不会让它看到分布外的输入【推断】。
4. **实现。** 用 bincount 统计物化缓存中 8 遍子集的 token 计数；加载最终检查点；替换输入表的行；跑 Paloma 评测。非最终检查点已在 2026-10-18 删除，但最终检查点仍在（[doc] open risks）。
5. **成本。** 每个检查点的 Paloma 评测约 1 GPU·h 以内【推断】。没有训练。
6. **预期效果与风险。** 效果大小未知。若计数为 0 的类型占最稀有十分位代价的一大部分，门控规则可能再降 0.005–0.02【推断】。在不重复检查点上应用同一规则作为对照，预期 ≈ 0。风险低。这个规则在训练端是合法的模型定义：它只用训练器自己能看到的计数。
7. **配对不重复 run。** 不需要训练；评测对照用不重复检查点。

### 排名 3：只切分稀有 token 的每遍重分词（输入与目标同时改）

1. **想法。** 第 2–8 遍中，每次出现 id ≥ K_split（例如 32000 或 8000）的 token，以概率 p（0.1、0.3）把它换成它的 8K 片段序列。输入和目标同时换。然后重新切成 4096-token 窗口。评测用标准切分。另做一个对照：只改输入不改目标（就是 cvd）。
2. **来源。**
   1. BPE-Dropout，NMT 中数据越少收益越大 ([Provilkov et al. 2020, arXiv 1910.13267](https://arxiv.org/abs/1910.13267))；Subword Regularization ([Kudo 2018, arXiv 1804.10959](https://arxiv.org/abs/1804.10959))。
   2. 苏剑林：训练时用带随机性的分词，"甚至能增强泛化能力" ([kexue.fm/archives/9762](https://kexue.fm/archives/9762))；随机分词的实现 ([9768](https://kexue.fm/archives/9768)、[9811](https://kexue.fm/archives/9811))。
   3. Data noising：目标侧噪声贡献了 MT 增益的大部分（+1.4 BLEU 中的 +1.0）([Xie et al. 2017, arXiv 1703.02573](https://arxiv.org/abs/1703.02573))。
   4. homotokens：在 ≥ 16 次重复时推迟过拟合，< 16 次时没有效果；作者保持目标为标准切分，理由是随机目标让标签含糊 ([Cosma et al. 2026, arXiv 2601.02867](https://arxiv.org/html/2601.02867v1))。
   5. StochasTok：训练时把 token 随机拆成合法的子 token 对 ([Sims et al. 2025, arXiv 2506.01687](https://arxiv.org/abs/2506.01687))。
3. **为什么针对本项目的机制。** 128K 剩下的代价主要在稀有目标上，而改输出行的做法都失败了（§2.2 第 1–3 条）。这个做法不动输出行，而是让"上下文 → 稀有 token"这个映射只在部分遍出现，其余遍出现的是"上下文 → 片段"。所以它作用于主干对稀有目标的记忆【推断】。均匀的 bpd0.1 已经领先 0.0117（[doc] Q10f）；均匀噪声的大部分落在不会过拟合的常见 token 上；只对稀有 token 切分能把噪声集中到代价所在的地方【推断】。
4. **实现。** 不需要重新跑分词器。在 [mat] 中加一个模式（例如 `MODE=rsplit`）：对第 2–8 遍的每个 token，按 (token 位置, 遍数, 种子) 的哈希决定是否用 expand map 展开，拼接后重新切窗口，同时套用 rs 的新顺序。训练时 `PASS_DATA=rsplit<p>` 按顺序读缓存，与 bpd 相同。在 vis 节点上建缓存，约 10 分钟【推断，按 bytes rs 缓存 586 s 的记录估计】。
5. **成本。** 每个设置一次 8 遍 run，≈ 30–36 H100·h。token 数会增加（bpd0.1 增加 4.06%），所以和 bpd 一样，步数按"覆盖所有 8 遍文本"确定，再核对 FLOPs。
6. **预期效果与风险。** 效果未知，这是对稀有目标代价的第一个直接测试。风险：(a) 模型把部分概率分给非标准切分，按标准切分计 bpb 时这部分概率浪费，所以 p 要小；(b) bpd 叠加在 cvd 上只降 0.003，说明输入侧有重叠；新增的效果只会来自目标侧；(c) homotokens 在 < 16 次重复时没有看到效果。
7. **配对不重复 run。** 不需要。

### 排名 4：按频率分级的 cvd 替换率

1. **想法。** 把固定阈值（id ≥ 8000，p = 0.5）换成每个 id 的概率 p_i = min(p_max, γ0 · c0 / c_i)，c_i 是该 id 在训练子集中的计数。从第 2 遍起，加 rs。
2. **来源。** Kneser-Ney data noising 的自适应噪声率 γ_AD(x) = γ0 · N1+(x, •) / c(x)：只出现一次的 token 用 γ0，常见 token 噪声率低得多；按频率打折扩大了好用的 γ0 范围 ([Xie et al. 2017, arXiv 1703.02573](https://arxiv.org/abs/1703.02573))。
3. **为什么针对本项目的机制。** cvd32k 说明最稀有的 token 贡献了大部分收益，而且不损失拟合；cvd p0.8 说明对较常见的稀有 token 多替换只会损失拟合（[doc] Q10h）。分级的替换率把替换集中在最稀有的行上。对截断词表，它也比固定阈值更自然，因为每个词表的"稀有"范围不同【推断】。
4. **实现。** 在 [tv] 的 cvd 中，把 `id in [8000, V−257)` 的判断换成查表 `bernoulli(p_table[id])`；p_table 在启动时从子集计数算出。抽签仍然是 (seed, step) 的确定函数。约 10 行代码。
5. **成本。** 128K 一次 8 遍 run；γ0 扫 2 个值 ≈ 60–70 H100·h。
6. **预期效果与风险。** 【推断】比 cvd fp2 + rs 再降 0.003–0.008。风险：与 cvd 的收益高度重叠，增量可能低于种子噪声（cvd 种子差 0.0075）。需要 2 个种子才能下结论。
7. **配对不重复 run。** fp2 版不需要。

### 排名 5：每一遍重新打包文档（新的窗口边界）

1. **想法。** 第 2–8 遍中，把子集的窗口打乱后拼接成一条长序列，循环平移一个随机偏移（1–4095），再切成 4096-token 窗口。每个 token 的前文长度和相邻文档都变了。
2. **来源。** 在 1.5B、10 亿 token 池的设置中：固定顺序 3.011，每遍打乱 2.977，每遍打乱并重新打包 2.971（batch 64 序列）；batch 512 时分别为 3.205、3.124、3.064 ([Min 2026, arXiv 2610.15965](https://arxiv.org/html/2610.15965))。Slowrun 中每遍打乱降 0.026，文档级打乱再降 0.005–0.013 ([qlabs-eng/slowrun](https://github.com/qlabs-eng/slowrun))。
3. **为什么针对本项目的机制。** 这是通用手段，对每个 tokenizer 都适用。rs 已经证明顺序有用（128K −0.008，8K −0.004）。8K 和字节的代价不集中在稀有行上，所以它们只能靠这类通用手段【推断】。
4. **实现。** 在 [mat] 加 `MODE=rp`（新顺序 + 新边界）。末尾不足一个窗口的 token 丢弃。缓存在 vis 节点上建。
5. **成本。** 每个 tokenizer 一次 8 遍 run。先测 128K 和 8K ≈ 60–70 H100·h。
6. **预期效果与风险。** 【推断】在 rs 之上再降 0.002–0.01。Min 的批量 64 结果（−0.006）和本项目的批量 128 最接近。项目的窗口探针（3072）没有改变代价，但那个探针在所有遍都用同一种短窗口，不是每遍换边界；fig-pos 显示代价不随上下文长度增长，这降低了收益的预期。风险低。
7. **配对不重复 run。** 不需要。

### 排名 6：Lazy Adam，只用于输入 Embedding

1. **想法。** 某一步中梯度全为 0 的 Embedding 行，这一步不更新参数。采用苏剑林的变体：m 和 v 照常衰减，只是参数不动。再测一个"半 Lazy"：未出现的行更新乘 q = 0.5。
2. **来源。** 苏剑林：所有带动量的优化器都会在 token 不出现时继续用历史动量更新它的 Embedding，"就算没有被反复采样的词，对应的 Embedding 也被反复更新了，就导致了过拟合"；Lazy 化后 IMDB 验证准确率从约 83.7% 升到 84.9% 以上 ([kexue.fm/archives/6869](https://kexue.fm/archives/6869))。在 Tiger 优化器下，低频 token 的 Embedding 分量达到 ±100；他给出的对策包括 Lazy 化和 Tied Embedding ([kexue.fm/archives/9736](https://kexue.fm/archives/9736))。
3. **为什么针对本项目的机制。** 【未验证计算】设 m = v = 0 的行在第 0 步收到梯度 g，之后不再出现。用本配方的 β1 = 0.9、β2 = 0.98，第 k 步的逐元素更新是 0.707 × 0.909^k × sign(g) × adam_lr。累计约 7.8 × adam_lr，是第一步的 11 倍，而且全部朝同一个上下文的符号方向。按 768 维、峰值 adam_lr 0.002 计算，一次出现让行移动约 0.43（L2），而计数 1–9 的稀有行范数只有约 1.6。一个每遍只出现一次的 token，两次出现之间相隔约 1430 步，v 已衰减到 0，所以每次出现都是新的"脉冲"。高频行每步都出现，梯度方向互相平均，没有这种放大。grad 消融说明减少稀有行收到的梯度事件就能拿到收益（§2.1 第 5 条）。Lazy Adam 把每次出现的移动从约 7.8 降到 0.707 个学习率单位。
4. **【分歧】** kexue 调研笔记用 muonh.py 的默认值 β2 = 0.95 算出约 13 倍；本配方实际 β2 = 0.98（[scal] L666），重算为约 11 倍。苏剑林本人在 9736 中说，Adam 的更新量随动量指数下降，所以这个问题在 Adam 下"可能不会有明显感知"。上面的计算说明累计放大不小，但这只是计算，要用实验判断。另外，标准 Lazy Adam（未出现的行 m、v 也冻结）会在下一次出现时带上上一次的动量，即跨遍累积同一方向【推断】，所以优先测苏剑林的变体。
5. **实现。** 在 [mh] 的 Adam 分支中，对 Embedding 参数：`mask = any(grad != 0, axis=-1, keepdims=True)`，`update = update * (mask + q * (1 - mask))`，从第 round(11444/8) 步起生效。按组的 `clip_by_global_norm` 之后零行仍是零行。约 10 行代码。
6. **成本。** 128K 和 8K 各一次 8 遍 run，q ∈ {0, 0.5} ≈ 120–140 H100·h；先只测 128K q = 0 和 q = 0.5 ≈ 60–70 H100·h。字节词表几乎每行每步都出现，是天然的阴性对照。
7. **预期效果与风险。** Lazy Adam 实际上是按频率分级的"减慢稀有行"，介于不改动和 fip（冻结）之间。fip 的 8 遍领先 0.009–0.010。【推断】fp2 版本领先 0.005–0.012；与 cvd 的收益重叠程度未知。风险：q = 0 时稀有行在第 2–8 遍的学习速度降到约 1/11，可能像 fip 一样损失拟合；fp2 版本只影响 8 遍 run。
8. **配对不重复 run。** fp2 版不需要；从第 0 步的版本需要。

### 排名 7：向片段均值衰减（decay-to-composition）

1. **想法。** 对 id ≥ 8000 的输入行，每步加一个解耦的拉力：e_i ← e_i − adam_lr(t) · λ · (e_i − stopgrad(片段行均值_i))。行可以在数据支持时自由移动，但它的方向被持续拉回片段均值。
2. **来源。** 苏剑林把权重衰减写成参数对更新量的滑动平均，记忆周期约为 1/(λη)，并建议多轮训练时让 1/(λη) 正比于单轮步数 ([kexue.fm/archives/11459](https://kexue.fm/archives/11459))。稀有词和常见词的 Embedding 占据不同的子区域 ([FRAGE, arXiv 1809.06858](https://arxiv.org/abs/1809.06858))。强权重衰减是数据受限预训练中效果最大的通用手段 ([Kim et al. 2025, arXiv 2509.14786](https://arxiv.org/html/2509.14786))。
3. **为什么针对本项目的机制。** 已确定的机制是"记忆在方向上"，重复让稀有行偏离片段均值（§2.3 第 3 条）。cvd 通过替换间接抵消这个偏离。这个拉力直接作用于方向，而且衰减的目标不是 0，所以不会像普通权重衰减那样缩小行范数【推断】。
4. **实现。** 在 [mh] 的 Adam 分支中，对 Embedding 参数在 `scale(-adam_lr)` 之后加一项：`- adam_lr * λ * mask_rare * (E - stop_gradient(P @ E))`，P 是由 expand map 建成的稀疏片段均值矩阵。按 11459 的建议，让记忆周期等于一遍：λ · adam_lr ≈ 1/1430，峰值时 λ ≈ 0.35【未验证计算】。扫 λ ∈ {0.1, 0.35, 1}。
5. **成本。** 128K，叠加在 cvd fp2 + rs 上，3 个 λ ≈ 90–110 H100·h。
6. **预期效果与风险。** 【推断】在 cvd fp2 + rs 上再降 0.003–0.01。风险：与 cvd 的机制重叠；λ 过大时等价于 cvin（训练和评测都用片段均值），而 cvin 损失不重复拟合。
7. **配对不重复 run。** 从第 2 遍生效时不需要；从第 0 步生效时需要。

### 排名 8：稀有目标位置的输出行梯度 dropout（"tgt-grad"）

1. **想法。** 从第 2 遍起，在目标 id ≥ 8000 的位置，以概率 p = 0.5 把目标列的 logit 换成 h · stopgrad(W_y)。数值不变，但这个位置不再给自己的输出行 W_y 任何梯度；隐藏状态 h 仍然接收梯度。这是 grad 消融在输出侧的镜像。
2. **来源。** 项目的 grad 消融（[doc] Q10i）。稀有 token 的输出行主要收到"压低"梯度，导致表示退化 ([Gao et al. 2019, arXiv 1907.12009](https://arxiv.org/abs/1907.12009))；对稀有 token 的部分梯度做门控能改善 LM ([Yu et al. 2022, arXiv 2109.03127](https://arxiv.org/abs/2109.03127))。
3. **为什么针对本项目的机制。** 剩余代价在稀有目标上。这个做法比冻结（fop）和 0.1× 减速（G）温和得多：它只去掉一半的"拉高"梯度，保留所有"压低"梯度。
4. **实现。** 在 lm_head 的 loss 计算中，用 gather 取出目标列，按位置掩码替换为 stop_gradient 版本。注意 AdamH 按整个表确定步长：fop 的第一次运行因此被混淆（保留的行拿到约 4 倍步长，[doc] Q5b）。要记录 AdamH 的全表更新范数，确认没有类似的重新分配。
5. **成本。** 128K 一次 8 遍 run ≈ 30–36 H100·h。
6. **预期效果与风险。** 风险高。G（0.1× 减速）的 8 遍结果比 128K 更差（1.4870 对 1.4651）；K 和 L 说明剩余代价不经过稀有输出行（§2.3 第 4 条）。【推断】最可能的结果是"无变化或略差"。它的价值主要是诊断：若它也失败，就进一步确认稀有目标代价在主干。
7. **配对不重复 run。** 不需要。

### 排名 9：输入 Embedding 权重衰减（审稿人一定会要的基线）

1. **想法。** 在 Adam 分支中加 `optax.add_decayed_weights(λ)`，只作用于输入 Embedding，λ ∈ {0.1, 0.35}（0.35 对应峰值时记忆周期一遍）。
2. **来源。** 在 10 亿 token 池中，Tied Embedding 加正的 Embedding 权重衰减给出最好的结果（1.5B：2.971 → 2.946，batch 64）([Min 2026, arXiv 2610.15965](https://arxiv.org/html/2610.15965))。λ = 1.0 的权重衰减把过拟合项系数降约 70% ([Lovelace et al. 2026, arXiv 2605.01640](https://arxiv.org/abs/2605.01640))。固定数据下最优权重衰减是标准值的 30 倍 ([Kim et al. 2025, arXiv 2509.14786](https://arxiv.org/abs/2509.14786))。记忆周期 ([kexue.fm/archives/11459](https://kexue.fm/archives/11459))。
3. **【分歧】** 文献支持权重衰减；项目的 Q10n 发现稀有行范数不随重复增长，所以"控制范数"不是要解决的问题（[doc] Q10n）。【推断】更糟的是：Adam 的每步更新大小与行范数无关，衰减让行变小后，同样大小的一步会让行转动更大的角度，所以方向记忆可能更快。Qwen3 是 pre-norm，第一层的输入经过 RMSNorm，行的大小对第一层不重要，只改变它在残差流中的占比。文献中的结果都是 AdamW 加全部权重衰减，不是只加在 Embedding 上。
4. **实现。** 1 行代码。
5. **成本。** 128K 和 8K，不重复与 8 遍各一次 ≈ 120–140 H100·h。
6. **预期效果与风险。** 【推断】很小，或为负。把它排在第 9，是因为它是审稿人会要求的标准基线，不是因为预期它有效。
7. **配对不重复 run。** 需要（从第 0 步生效）。

### 排名 10：第 2–8 遍提高 MuonH 学习率（记忆周期论证）

1. **想法。** 从第 2 遍起，把 MuonH 的学习率乘以 m ∈ {1.5, 2}，保留 cosine 形状并退火到 0。
2. **来源。** [mh] 文档字符串说 MuonH 的学习率对应 Muon + WD 配置中的 sqrt(lr · weight_decay)。记忆周期 1/(λη) ([kexue.fm/archives/11459](https://kexue.fm/archives/11459))。强权重衰减配方 ([Kim et al. 2025](https://arxiv.org/html/2509.14786)；[Xu et al. 2026, arXiv 2606.06888](https://arxiv.org/html/2606.06888v2))。
3. **为什么。** 【未验证计算】在保持范数的球面上，每步相对转角为 η 时，旧方向的分量每步衰减约 η²/2，所以记忆周期约为 2/η²。本配方峰值 η = 0.01，记忆周期约 20,000 步，长于整个训练（11,444 步），远长于一遍（约 1,430 步）。按苏剑林"记忆周期正比于单轮步数"的建议，要让记忆周期等于一遍，峰值 η 需要约 0.037。这个推导把 MuonH 的更新近似为与权重正交，没有验证。
4. **实现。** 在学习率调度中，step ≥ round(11444/8) 时乘以 m。
5. **成本。** 128K 和 8K 各 2 个 m 值 ≈ 120–140 H100·h；要声称"补救重复"，还要同样改动的不重复 run。
6. **预期效果与风险。** 不确定。风险：较大的学习率也会改变不重复结果，而且可能不稳定。这是通用手段，不针对稀有行。
7. **配对不重复 run。** 需要。

### 排名 11：最后 1–2 遍的 EMA 或 SWA

1. **想法。** 维护参数的 EMA（窗口约一遍，β = 1 − 1/1430），用 EMA 权重评测；或者对最后 2 遍边界的检查点做 SWA。
2. **来源。** Slowrun 的记录：EMA −0.012 到 −0.018，SWA −0.008 到 −0.012 ([qlabs-eng/slowrun](https://github.com/qlabs-eng/slowrun))。苏剑林：权重平均与学习率衰减可以互相折算，等权平均不如滑动平均 ([kexue.fm/archives/11804](https://kexue.fm/archives/11804))。
3. **为什么。** 通用手段，所有 tokenizer 都适用。
4. **风险。** Slowrun 的收益是在 WSD 类调度上测的；本配方 cosine 退火到 0，平均的额外收益可能更小【推断】。EMA 也会改善不重复 run，所以必须对两种 run 都做。
5. **成本。** 需要新 run（非最终检查点已删除）。128K 与 8K 的配对 ≈ 120–140 H100·h。
6. **配对不重复 run。** 需要。

### 排名 12：固定的 log-unigram logit 偏置（logit adjustment）

1. **想法。** logits ← logits + τ · log p̂，τ ∈ {0.5, 1}，p̂ 是平滑的 unigram 频率，不训练。训练和评测都加，所以模型族不变，bpb 计算合法。
2. **来源。** 苏剑林：拟合 log p(y|x)/p(y) 等价于在 logit 上加 log p(y)，"一般情况下，τ = 1 的效果就已经接近最优了" ([kexue.fm/archives/7615](https://kexue.fm/archives/7615))。长尾分类中的 logit adjustment ([Menon et al. 2020, arXiv 2007.07314](https://arxiv.org/abs/2007.07314))。
3. **为什么针对本项目的机制。** Qwen3 的 lm_head 没有 bias，AdamH 又固定整个表的 Frobenius 范数，所以频率先验要占用输出行的范数预算【推断】。固定偏置把先验拿走，稀有行只需学条件信息。是否减少记忆，没有任何证据。
4. **【分歧】** 一份笔记建议 p̂ 用整个语料计算；另一份建议只用训练子集。本报告建议：8 遍 run 只用 1/8 子集的计数，不重复 run 用它自己的数据计数，这样两种 run 的数据预算都诚实。
5. **实现。** logits 计算之后加一个常数向量。几行代码。
6. **成本。** 必须从第 0 步生效，所以每个 tokenizer 要配对两次 run。128K 与 8K ≈ 120–140 H100·h。
7. **预期效果与风险。** 【推断】很小。风险低。
8. **配对不重复 run。** 需要。

### 排名 13：以不重复训练 loss 为水位的 Flooding

1. **想法。** 8 遍 run 中，batch 平均损失 L 换成 |L − b(t)| + b(t)，b(t) 取同一 tokenizer 不重复 run 在同一步的平滑训练 loss（W&B 日志中已有）。
2. **来源。** 苏剑林推出：低于水位后一步下降一步上升，平均相当于以学习率 ε²/2 最小化梯度范数；他自己试过"有些情况下会有轻微的提升"，"不如自己直接加梯度惩罚好" ([kexue.fm/archives/7643](https://kexue.fm/archives/7643))。
3. **为什么。** 通用手段，自动为每个 tokenizer 定水位。第 1 遍时不触发。
4. **风险。** batch 级的上升作用于所有 token，包括没有被记住的常见 token；而代价集中在稀有 token 上。苏剑林本人的证据弱。
5. **成本。** 1 行代码；128K 与 8K 各一次 8 遍 run ≈ 60–70 H100·h。
6. **配对不重复 run。** 不需要。

### 排名 14：只扰动出现行的 Embedding FGM

1. **想法。** 第一次前向和反向得到 Embedding 梯度 G；对出现的行加 δ_i = ε · G_i / ‖G_i‖；第二次前向和反向用扰动后的 Embedding 更新。
2. **来源。** NLP 对抗训练把扰动加在 Embedding 参数矩阵上，"仍然能起到正则化的作用" ([kexue.fm/archives/7234](https://kexue.fm/archives/7234))；随机噪声"不够特异性" ([kexue.fm/archives/7466](https://kexue.fm/archives/7466))。
3. **为什么排最后。** 每次使用都要第二次前向和反向。每 4 步用 1 次也要多 25% 算力，所以必须相应减少步数才能保持同算力。
4. **配对不重复 run。** 需要。

## 4. 已排除的想法及原因

1. **集成与蒸馏。** 在数据受限设置中收益最大（8 × 300M 集成蒸馏回 300M 保留 83% 的增益），但要多倍算力 ([Kim et al. 2025](https://arxiv.org/html/2509.14786)；[q0, arXiv 2606.03938](https://arxiv.org/abs/2606.03938))。违反同算力规则。
2. **扩散目标、任意顺序目标。** 扩散只在几百遍后才超过 AR；在强权重衰减下 AR 与扩散相当 ([Prabhudesai et al. 2025](https://arxiv.org/html/2507.15857)；[Xu et al. 2026](https://arxiv.org/html/2606.06888v2))。8 遍远低于交叉点。
3. **MIR（掩码副本辅助损失）。** 约相当于 1.3 倍数据，但每步两次前向 ([Xu et al. 2026](https://arxiv.org/html/2606.06888v2))。违反同算力规则。
4. **改写（WRAP）、混入代码、合成数据。** 改变训练分布，还需要生成模型的算力 ([Maini et al. 2024, arXiv 2401.16380](https://arxiv.org/abs/2401.16380)；[Muennighoff et al. 2023](https://arxiv.org/html/2305.16264))。
5. **更小的 batch。** 文献在重复数据下支持更小的 batch ([Min 2026](https://arxiv.org/html/2610.15965))，但项目的 batch 96（1.33× 步数）探针没有改变代价（[figs] fig-steps）。
6. **屏蔽稀有目标、Goldfish loss。** rm8kp5 崩溃到 2.845（[doc] Q10）。Goldfish 针对逐字复现，不针对留出集 loss ([Hans et al. 2024, arXiv 2406.10209](https://arxiv.org/abs/2406.10209))。
7. **冻结、减慢或硬组合稀有输出行。** fop、G、L、K、cvout、fo8k 全部失败（§2.2 第 1–2 条）。
8. **共享的 UNK 行、低秩表。** unk 损失拟合 0.018；lr48 拟合比 8K 还差（[doc] Q9、Q10i）。
9. **n-gram 输入表（Over-encoding、Engram）。** 项目早先结果：重复数据下反转，2.4 遍时比基线差 0.153。它们增加记忆面。
10. **对稀有行做范数裁剪或逐行超球面。** 稀有行范数不随重复增长（[doc] Q10n），裁剪不会触发 ([kexue.fm/archives/11729](https://kexue.fm/archives/11729))。
11. **Label smoothing、z-loss、TVD/γ-CE、其他恰当评分规则。** Label smoothing 在 Xue 2023 中只有轻微改善 ([arXiv 2305.13230](https://arxiv.org/html/2305.13230))，而且把概率分给错误的 token 会直接提高 bpb【推断】。z-loss 没有任何重复数据的证据。γ-CE 针对难样本，不针对被记住的样本 ([kexue.fm/archives/9526](https://kexue.fm/archives/9526))；换成其他恰当评分不改变最优解，也没有减轻记忆的证据 ([kexue.fm/archives/11854](https://kexue.fm/archives/11854))。
12. **按频率加权损失。** 提高稀有 token 的权重会加重它们的记忆；降低权重会直接损害稀有 token 的 bpb ([kexue.fm/archives/7708](https://kexue.fm/archives/7708))。
13. **homotokens 辅助编码器。** 增加约 1M 参数；在 < 16 次重复时没有效果 ([Cosma et al. 2026](https://arxiv.org/html/2601.02867v1))。
14. **部分 Tie（稀有输入行用输出行参数化）。** 输入用 Adam、输出用 AdamH，Tie 会改变优化器分组；AdamH 的全表范数约束会把输入行也绑住；Tie 还引起初始损失问题 ([kexue.fm/archives/9698](https://kexue.fm/archives/9698)、[9736](https://kexue.fm/archives/9736))。风险高，暂不测。
15. **梯度 dropout（ChildTuning-F）。** 在带动量的优化器下，梯度为 0 不代表更新为 0 ([kexue.fm/archives/8764](https://kexue.fm/archives/8764))。若要随机跳过稀有行的更新，应在更新量上做掩码，这就是排名 6 的实现点。

## 5. 未解决的问题与建议的诊断

1. **剩余的稀有目标代价在主干还是在输出头？** 建议诊断：在 128K 8 遍最终检查点上，只微调 lm_head 几百步，用新数据；若稀有目标代价大幅下降，代价在输出头，否则在主干。这一步用到新数据，只能作诊断，不能作补救。
2. **覆盖缺失占多少？** 见排名 2：把最稀有十分位按子集计数（0、1–7、≥ 8）拆开。
3. **64K/32K/16K 的代价分布。** 没有分十分位分析，没有第二个种子。它们的差距排序（0.075、0.059、0.044）还没有经过种子检验。
4. **输出头的逐行行为。** 没有记录稀有输出行的范数或它与片段输出行的余弦随重复如何变化。lm_head 只在整体上保持范数，行之间可以重新分配范数。
5. **代价随遍数的曲线。** 只有 2.4 遍和 8 遍两个点。用 2、4、8 遍画 cost(遍数)，可以按苏剑林的形式 α10 · (K/D)^γ10 为每个 tokenizer 拟合指数，检验"128K 的系数更大但指数相同"这一假设 ([kexue.fm/archives/11833](https://kexue.fm/archives/11833))【推断】。
6. **两种机制的区分。** 大词表更容易记忆，Kharitonov 等人认为主因是序列更短 ([arXiv 2110.02782](https://arxiv.org/abs/2110.02782))；另一种解释是稀有 token 充当记忆的"钥匙" ([Stoehr et al. 2024, arXiv 2403.19851](https://arxiv.org/abs/2403.19851))。项目的证据（代价集中在稀有行、方向记忆）更支持后者。干净的检验：在序列长度不变时，把稀有 id 哈希进几百个桶；若代价下降，说明是"钥匙"机制【推断】。
7. **缺失的记录。** 文档引用的"原因 4、6、7、8"清单不在已读文档中（[doc] L47）。
8. **其他模型大小。** 520m 只有 128K、8K、字节；130m 没有任何补救实验；64K/32K/16K 没有 520m 运行。
9. **定义问题。** 一个设置的"自己的不重复点"是用改动后的不重复 run（例如 cvd 1.3916），还是用不改动的 tokenizer？fp2 设置让两者相同。本报告的差距一律用不改动的不重复线。

## 6. 已排队的实验：文献的预测

排队的实验都是种子 0、只改第 2–8 遍，所以不重复点保持各 tokenizer 自己的。

1. **残差 dropout 0.1，从第 2 遍起（drop-fp2，15954894；128K 与 8K）。**
   1. 支持的证据：在多轮训练中，"只用 dropout 最有效"，推迟开启的 dropout 与从头开启的最终效果相当 ([Xue et al. 2023, arXiv 2305.13230](https://arxiv.org/html/2305.13230))；"late dropout" 用于过拟合的模型 ([Liu et al. 2023, arXiv 2303.01500](https://arxiv.org/abs/2303.01500))；96 遍时 dropout 对 AR 有帮助 ([Ni et al. 2025, arXiv 2511.03276](https://arxiv.org/html/2511.03276v1))；Slowrun 的基线都用 dropout 0.1 ([qlabs-eng/slowrun](https://github.com/qlabs-eng/slowrun))。
   2. 反对的证据：单轮预训练中不用 dropout 更好 ([Liu, Bauer, Manning 2025, arXiv 2505.24788](https://arxiv.org/abs/2505.24788))，但这个结论不适用于从第 2 遍起的设置；140M、50 遍时 attention dropout 没有改善验证 loss ([Prabhudesai et al. 2025](https://arxiv.org/html/2507.15857))。
   3. **【分歧】** dropout 有益（Xue、Ni、Slowrun）与无效或有害（Prabhudesai、Liu-Bauer-Manning）。分歧的主要来源是遍数和是否推迟开启。
   4. 预测【推断】：小幅收益。128K 降 0.003–0.01，8K 降 0.002–0.006。它不针对稀有行，所以 128K 与 8K 的绝对收益应该相近。它作用于主干，所以要看它是否降低稀有目标十分位的代价：这是第一个测试"稀有目标代价在主干"的实验。
2. **残差 dropout 0.2（drop02-fp2，15960983）。** Xue 的 0.2–0.3 最优值出现在 256 遍和 XL/MoE 模型上。本设置只有 8 遍，比较温和。预测【推断】：比 0.1 差，或者与 0.1 持平。
3. **dropout 0.1 + rs（drop-fp2-rs，15961018）。** 已知的叠加情况：cvd 与 rs 完全叠加，cvr 与 rs 部分叠加，bpd 与 cvd 几乎不叠加（§2.1）。dropout 与 rs 作用于不同对象（参数噪声对数据顺序），预测【推断】：大部分叠加。
4. **输入行 dropout 0.1（inzero-fp2，15961203）。** 每个位置以 0.1 的概率把输入行置零，保留的行乘 1/(1−p)；它模仿 AWD-LSTM 的 Embedding dropout ([Merity et al. 2017](https://arxiv.org/abs/1708.02182))。注意 AWD-LSTM 在一个序列内丢掉整个词类型，而这里按位置独立丢。它作用于所有位置，主要是常见 token；对稀有行只等于 10% 的 grad 消融。预测【推断】：128K 降 0.002–0.008，小于 cvd 的 0.018；8K 接近 0。
5. **随机替换输入 token 0.1（inrand-fp2，15961253）。**
   1. 支持的证据：150M、100 遍时，15% 的随机替换降 0.174 ([Chen et al. 2026, arXiv 2606.16246](https://arxiv.org/html/2606.16246v1))。反对的证据：140M、50 遍时，token 掩码没有效果 ([Prabhudesai et al. 2025](https://arxiv.org/html/2507.15857))。**【分歧】**
   2. 本项目特有的一点：抽样在 V − 256 个普通 token 上**均匀**进行（[drop] L151），而 Xie 2017 的 unigram 噪声按频率抽样。【未验证计算】128K 的第 2–8 遍约有 52.5 亿个输入位置，10% 被替换，每个 id 平均多出约 4,100 次随机上下文中的输入出现。这远多于最稀有 token 在子集中的自然计数。所以对 128K，这个实验主要是在用噪声上下文大量训练稀有输入行；对 8K，额外出现次数相对于自然计数小得多。
   3. 预测【推断】：128K 的结果方向不确定。一种可能：模型学会不信任稀有输入行，效果类似 cvd。另一种可能：稀有行被噪声破坏，稀有输入十分位代价上升。8K 的效果应该小。建议在结果出来后先看稀有输入十分位。
6. **64K/32K/16K 的 rs（rs-mid 15961318，rs-v16k 15961377）。** 文献支持每遍打乱（Min 2026：−0.034，batch 64；Slowrun −0.026）。项目内插：128K −0.008，8K −0.004。预测【推断】：每个降 0.004–0.008，远不能关掉 0.075、0.059、0.044 的差距。它们是排名 1 的基础。
7. **字节种子 1（15832611）与字节 + rs（15883244）。** 字节的差距 0.0041 小于种子噪声。2.4 遍时代价已为 −0.0024。预测【推断】：rs 让字节的 8 遍结果达到或低于自己的不重复线 1.3695。结论需要两个种子都满足。若成立，字节是第一个达到目标的 tokenizer。

## 结论

这次调研改变了下一批实验的重心。到现在为止，项目的进展都来自输入侧和数据顺序，而 128K 剩下的约 0.05 bpb 主要在稀有目标上，而且已经证明它不经过稀有输出行。所以下一批实验中真正新的信息来自三处：已排队的 dropout（第一次正面测试主干）、只切分稀有 token 的重分词（第一次在不动输出行的情况下作用于稀有目标）、以及只需评测的覆盖诊断（可能说明一部分"代价"根本不是记忆，而是 1/8 子集里没有出现的 token 类型）。对"每种 tokenizer"这一目标，最大的总差距在 64K、32K、16K，它们还没有任何补救实验；把已经验证的 cvd fp2 + rs 移植过去，关掉的总差距最多。

第二个启示是：本配方几乎没有能让模型"遗忘"的机制。输入 Embedding 没有权重衰减；按记忆周期计算，MuonH 线性层在峰值学习率下的记忆周期约 20,000 步，是整个训练（11,444 步）的约 1.7 倍【未验证计算】。文献中最强的通用手段（强权重衰减）在这个栈上没有直接的旋钮。Lazy Adam、向片段均值衰减、提高后几遍的 MuonH 学习率，都是在这个栈上实现"遗忘"的不同方式。它们各自的价值，要等第一批结果和诊断出来后再判断。
