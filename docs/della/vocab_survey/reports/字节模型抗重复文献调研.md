# 没有论文检验字节模型抗重复：空白成立，混杂要先拆开

调研日期：2026-10-22。输入：`research_notes/字节模型抗重复文献调研/` 的 5 份笔记，以及上一轮报告 `reports/重复数据词表过拟合补救调研.md` 和它的笔记。

**结论先行。** 笔记没有找到任何论文在固定文本量下比较字节（或字符、小词表）模型与 BPE 模型的多轮重复代价。所以"固定文本下字节模型抗多轮重复"是文献空白。唯一的直接命中是项目主人自己的页面，它不是独立证据。最接近的先行工作是 Kharitonov 等 2021：BPE 词表从 611 增到 18,336 时，小模型更容易记住训练数据。但它只测训练集记忆，不测留出集 loss，不含字节，模型只有 18M–162M 参数，也没有同行评审。其他相关工作都只覆盖一侧：字节模型论文只做单遍训练或按 FLOPs 对齐；重复数据论文只用一种 tokenizer。这个空白有一个风险。我们的字节模型与 128K 模型不只差在词表上：字节模型约有 103M 参数，128K 模型约有 300M 参数；同样的文本，字节模型有 4.74 倍的预测目标和 4.74 倍的优化步数。用 arXiv 2610.05591 的重复代价公式，只代入参数总数（含嵌入）和不重复目标数，就能预测字节约 0.004 bpb、128K 约 0.061 bpb、8K 约 0.016 bpb，与实测的排序和量级一致【未验证计算】。这篇论文可能出自项目主人或合作者，所以本报告只把它当作待检验的假设，不把它当作独立证据。因此，论文要声称的结论需要先回答一个问题：字节的优势来自"没有稀有行"，还是只来自"参数更少、目标更多"。正在运行的等文本窗口实验能排除步数这一解释。正在运行的字节 16/32/64/128 遍实验能检验公式。还需要一个新实验来区分剩下的两种解释：给字节模型加上一张 128K 规模的输入查找表。

标记说明：
1. 【未验证计算】表示本报告或笔记作者自己的数值计算，没有人复核，也没有实验验证。
2. 【推断】表示推理，没有实验或文献直接支持。
3. 【分歧】表示来源之间有冲突。
4. 【仅摘要】表示笔记只读了摘要、搜索摘要或凭记忆核对了标题，没有读正文中的相关段落。

## 1. 我们的字节结果带有三个混杂：参数量、目标数、步数

### 1.1 设置与结果（项目主人提供的事实）

1. 模型：Qwen3 式 decoder，隐藏维度 768，12 层，"300m"。
2. 输入嵌入与输出头不共享。128K 词表时，每张表约 98.5M 参数，两张表共约 197M；非嵌入主体约 103M。
3. 优化器：线性层用 MuonH，嵌入用 Adam。
4. 数据：fineweb-edu，固定文本量；batch 128 × 4096 token。
5. 步数：128K 用 11,444 步，字节用 54,247 步。两个步数都覆盖 8 遍 run 的全部 8 遍。
6. 8 遍代价 = "8 遍读同一个随机 1/8 文本"减"读不重复文本"，单位为 Paloma bits per byte（bpb）。

| tokenizer | 8 遍代价（bpb） |
|---|---|
| 128K | 0.082 |
| 64K | 0.075 |
| 32K | 0.059 |
| 16K | 0.044 |
| 8K | 0.026 |
| 字节（256） | 0.004（种子 0）；2 种子均值 +0.0003 |
| 字节，520m | 0.027 |
| 字节，每遍新顺序 | +0.0043 |

其他已知结果：
1. 128K 在固定文本下用 1.33 倍步数（更小的 batch），代价不变。
2. 对 128K 稀有 token 输入行的干预，关掉约一半与 8K 的差距。
3. 字节模型的不重复结果是 1.3695 bpb，128K 是 1.3828 bpb（种子 0）。所以在本设置中，字节模型在不重复文本上并不比 128K 差（[项目记录](/scratch/gpfs/GROUP/USER/project/marin/docs/della/vocab_survey/research_notes/重复数据词表过拟合补救调研/project_experiments.md)）。
4. 正在运行：(a) 等文本窗口：每个 tokenizer 都约 11,444 步，窗口 = 4096 × token 比；(b) 字节 16、32、64、128 遍。

### 1.2 由这些事实推出的量【未验证计算】

| 量 | 128K | 8K | 字节 |
|---|---|---|---|
| 两张嵌入表参数 | 约 197M | 约 12.6M | 约 0.4M |
| 参数总数 N_total | 约 300M | 约 116M | 约 103.4M |
| 全部训练 token（目标） | 6.00B | 约 8.1B（按 1.35 倍） | 28.44B |
| 每遍不重复目标 U | 0.75B | 约 1.01B | 3.56B |
| token/参数 | 约 20 | 约 70 | 约 275 |
| 每遍步数 | 约 1,430 | 约 1,930 | 约 6,781 |

说明：
1. 字节模型的参数总数约为 128K 模型的 1/3。名字都叫"300m"，但字节模型实际约 103M 参数。
2. 8K 的 1.35 倍 token 比来自笔记，没有在本报告中复核。
3. 笔记 `repetition_mechanisms.md` 曾假设 N = 0.30B、共享的 1024 维嵌入。这两个假设与上面的事实不符。本报告用上面的数字重算。

### 1.3 三个混杂

在固定文本下，字节模型与 128K 模型同时在以下各方面不同：
1. **参数量。** 字节模型少约 197M 嵌入参数。
2. **目标数。** 同样的文本，字节模型有 4.74 倍的预测目标。
3. **步数。** 同样的文本，字节模型走 4.74 倍的优化步。两次重复之间相隔 4.74 倍的步数。
4. **序列长度。** 同样的文本，字节序列长 4.74 倍。
5. **稀有行。** 字节词表没有稀有行。256 行在每一步几乎都出现。

"字节模型抗重复"这一说法，要先说明它来自哪一项。

### 3.2 Kharitonov 等 2021：唯一改变词表并测记忆的受控研究

1. 主张：BPE 词表大小"greatly affects both ability and tendency"去记忆；大词表时 Transformer 更易拟合随机映射，更易受成员推断攻击，LM 更常复现训练数据（[arXiv 2110.02782](https://arxiv.org/abs/2110.02782)）。
2. 随机标签（SNLI，367,388 个样本，最多 500 遍）：1 层 Encoder 在词表 611 时拟合约 87%，在 18,336 时超过 98%；LM 和 MLM 从约 94% 和 97% 升到 100%（[arXiv html v2](https://arxiv.org/html/2110.02782v2)）。
3. 成员推断（100 遍）：三种架构的 AUC 都随词表单调上升（[arXiv html v2](https://arxiv.org/html/2110.02782v2)）。
4. PAQ 问答复现（约 1,400 万对，70 遍，词表 1,280–20,776）：精确复现率随词表上升（[arXiv html v2](https://arxiv.org/html/2110.02782v2)）。
5. 参数量控制：嵌入维度随词表缩小，使总参数约等于 18.2M–18.3M，趋势不变（[arXiv html v2](https://arxiv.org/html/2110.02782v2)）。
6. 机制排除：
   1. 不可压缩的随机二进制串上效果仍在，所以不是"去掉冗余"。
   2. 均匀频率的理想化合并（词表 2/4/16/256）上效果仍在，所以不是频率偏斜（附录 D）。
   3. 用"同义 token"把词表加倍而长度不变，记忆模式不同，所以不是词表大小本身。
   4. 作者通过排除法推测主因是序列变短。这是推测，没有直接检验（[arXiv html v2](https://arxiv.org/html/2110.02782v2)）。
7. 【分歧】同义 token 控制的方向：本轮笔记写"记忆先下降"或只写"different memorization pattern"；上一轮笔记写"先急剧变差，后来才有帮助"。本轮笔记 `rare_tokens_embeddings.md` 明确说没有读到第 5.2 节，无法判断。
8. 翻译附录（En–Nl，800 万对，BPE 10k/20k/40k/80k）：早停前的遍数为 100/80/71/65，小词表训练更多遍才停（[arXiv html v2](https://arxiv.org/html/2110.02782v2)）。
9. 局限：最小的真实文本词表约 611，没有字节；没有 128K；模型 4–12 层；测训练集记忆，不测留出 loss；arXiv 上没有同行评审的会议信息。

这项工作预测了我们的排序（128K > 64K > … > 8K > 字节）。我们的结果把它从小模型的记忆探针推广到 300m 预训练的 Paloma bpb，并加上了字节端点【推断】。

### 3.3 词表缩放研究：数据少时小词表更好，但没有测重复

1. Tao 等（NeurIPS 2024）：302M 非嵌入参数时，数据成为瓶颈后最优词表从 16K 降到 10K，作者称其为"a mechanism to prevent over-fitting"。2.87B 时，"数据不足"条件下 24K 胜 32K（平均 43.9 对 43.2）（[arXiv html](https://arxiv.org/html/2407.13623v3)）。这里的"数据不足"是 token 预算更小，不是多遍重复。
2. Takase 等（ACL 2025 Findings）：在固定 1 遍文本的条件下，英文平均分从 5K 的 47.9 升到 500K 的 49.4；日文从 49.8 升到 56.2。作者指出，固定 token 数的比较让大词表"看到更多数据"（[arXiv html](https://arxiv.org/html/2406.16508)）。这与我们的 2.4 遍结果一致：遍数少时，词表对代价没有明显影响。
3. Chung & Kim（NeurIPS 2025）：词表 24K–196K，收益来自约 2,500 个最常见词，稀有词的 loss 上升（[arXiv 2508.15390](https://arxiv.org/abs/2508.15390)）。

### 3.4 字节模型论文：讲"数据效率"，不讲"抗重复"

1. ByT5 用与 mT5 相同的 token 数训练，因此"pre-trained on 4× less text"。它在 Small 和 Base 尺寸上胜 mT5（GLUE Small 80.5 对 75.6）。作者推测字节模型"may be more data efficient learners"（[ByT5](https://ar5iv.labs.arxiv.org/html/2105.13626)）。
2. H-Net 在 100B token 的 FineWeb-Edu 子集上，按每 batch 字节数和每字节 FLOPs 对齐，"every model sees the same underlying data in each minibatch"。XL 最终 bpb：Transformer 0.730，1 阶段 H-Net 0.728，2 阶段 0.715。DNA 上约少 3.6 倍数据达到同样困惑度（[H-Net HTML](https://arxiv.org/html/2507.07955v2)）。这是方法上最接近固定文本的设计，但只训练一遍。
3. BLT 按 FLOPs 对齐。BPE 在小预算时更好，在计算最优点之后不远处被 BLT 超过：约 3.1E8 推理 FLOPs/字节时，交叉点在 150B 字节（[BLT HTML](https://arxiv.org/html/2412.09871)）。
4. Efficiency Gap（2026）：按计算对齐，字节 AR 模型在 bpb 1.0 时需要约 7.9 倍算力，在 0.8 时约 2.3 倍（[Efficiency Gap HTML](https://arxiv.org/html/2605.12928)）。
5. EvaByte 声称"5x less training data"，但比较对象用不同数据，页面没有推导 5 倍（[EvaByte blog](https://hkunlp.github.io/blog/2025/evabyte/)）。
6. MambaByte 实际训练了多遍 PG-19（SpaceByte 论文说是 14 遍），但没有不重复对照（[SpaceByte HTML](https://arxiv.org/html/2404.14408)；[MambaByte HTML](https://arxiv.org/html/2401.13660)）。MambaByte 的"0.63× less compute and training data"与它自己表中 30B 对 80B 字节（0.375 倍）不一致（笔记标记）。

这些"数据效率"都指单遍中每个不重复字节带来的 loss 下降。我们测的是重复造成的 loss 损失。这是两个不同的量。

### 3.5 两个反例：字节模型不是不会过拟合

1. Al-Rfou 等 2019：64 层字符 Transformer 在 9,000 万字符的训练集上训练，"necessitated aggressive dropout rates of 0.55"。笔记按 512 字符上下文估算约 230 遍【未验证计算】（[Al-Rfou](https://ar5iv.labs.arxiv.org/html/1808.04444)）。
2. Edman 等（TACL 2024）：ByT5 在 400 句对时比 mT5 高最多 10 chrF++，到 450 万句对时只高约 1.2。但 ByT5 对未见相关语言的零样本 chrF++ 从 37.7（1 万对）降到 23.4（25 万对），作者解读为 ByT5 记住了源—目标共现（[Edman et al.](https://arxiv.org/html/2302.14220v3)）。
3. 本项目 520m 字节模型的 8 遍代价是 0.027 bpb。

所以论文中的说法应限定为"在 8 遍、约 103M 参数时几乎不损失"，而不是"字节模型不受重复影响"。

### 3.6 重复数据研究（一种 tokenizer）给出的量级

1. Muennighoff 等：最多 4 遍"negligible changes to loss"；重复 token 的价值以 R*_D = 15.39 为 1/e 尺度衰减（[arXiv html](https://arxiv.org/html/2305.16264)）。
2. Hernandez 等 2022：把 0.1% 的数据重复 100 遍，800M 模型降到 400M 模型的水平；中间的重复范围造成最大损害（[arXiv 2205.10487](https://arxiv.org/abs/2205.10487)）。
3. Chudnovsky 等 2026：Qwen3 式 344M、FineWeb-Edu-Dedup；重复文档占 10% FLOPs 时，最差的重复次数等于少用 1/3 算力（[arXiv 2606.24998](https://arxiv.org/abs/2606.24998)）。
4. Xue 等 2023："larger models are more susceptible to overfitting under token-crisis conditions"；dropout 有效（[arXiv html](https://arxiv.org/html/2305.13230)）。
5. Lovelace 等 2026：过拟合项 P·R_D·(N/U_D)；权重衰减 0.1 改为 1.0，P 从 0.02305 降到 0.00681（[arXiv html](https://arxiv.org/html/2605.01640v1)）。
6. 2610.05591：ΔL = A·z^p，z = (R−1)·N_total/U，A = 0.0203 bpb，p = 1.07（R² = 0.96），U 是不重复的训练目标数；把嵌入参数计入 N 后"removes the size term"（[arXiv html](https://arxiv.org/html/2610.05591v1)）。

## 4. 先行工作指向五个机制，现有数据已经削弱其中两个

### 4.1 机制 A：每个不重复目标对应的参数量（含嵌入参数）

1. 文献：Lovelace 2026 的惩罚项与 N/U 成正比（[Lovelace et al.](https://arxiv.org/html/2605.01640v1)）；Tirumala 2022："larger language models memorize training data faster"（[arXiv 2205.10770](https://arxiv.org/abs/2205.10770)）；Xue 2023 说大模型更易过拟合；2610.05591 把嵌入参数计入 N。
2. 用 2610.05591 的公式代入第 1.2 节的数字【未验证计算】：

| tokenizer | z（N_total） | 预测（N_total） | 预测（只算主体 103M） | 实测 |
|---|---|---|---|---|
| 128K | 2.80 | 0.061 | 0.020 | 0.082 |
| 8K | 0.80 | 0.016 | 0.014 | 0.026 |
| 字节 | 0.20 | 0.0037 | 0.0037 | 0.004（2 种子 0.0003） |

3. 读法：
   1. 计入嵌入参数时，预测的排序和比值与实测一致。128K/8K 的预测比是 3.8，实测是 3.2。128K/字节 的预测比是 16.5。
   2. 只算主体参数时，128K 的预测只有 0.020，远低于 0.082。所以现有三点已经支持"嵌入参数也是重复数据的记忆容量"【推断】。
   3. 公式在 GPT-2 BPE、另一份数据、Muon + Adam 上拟合。对 BPE，实测比预测高约 1.3–1.6 倍。
4. 如果这个机制成立，字节的优势中约 2.9 倍来自参数少，约 4.74 倍来自目标多。"字节模型抗重复"就可以改写成"重复代价随每个不重复目标的参数量增长"。它也解释 520m 字节代价上升到 0.027，以及 1.33 倍步数实验的零结果（N 和 U 都没变）。

### 4.2 机制 B：稀有行充当记忆的"钥匙"

1. 文献：
   1. Morris 等 2025：模型约存 3.6 bits/参数；"The training documents with rarest words are typically the most memorized"（附录 A.3）（[arXiv 2505.24832](https://arxiv.org/abs/2505.24832)）。
   2. Stoehr 等 2024：第 1 层的一个注意力头关注段落中最稀有的 token，用来回忆被记住的段落【仅摘要】（[arXiv 2403.19851](https://arxiv.org/abs/2403.19851)）。
   3. Land & Bartolo（EMNLP 2024）：未充分训练的 token 占词表 0.1%–1%；Llama 3 8B（词表 128,256）确认 556 个；Gemma 2B（256,000）确认 3,161 个（[arXiv 2405.05417](https://arxiv.org/abs/2405.05417)）。
   4. Yu 等（ACL 2022）：冻结稀有 token 的共享嵌入行后，稀有组困惑度从 813.76 升到 3017.53（[arXiv 2109.03127](https://arxiv.org/abs/2109.03127)）。这与我们"冻结稀有输出行更差"一致。
   5. 苏剑林：带动量的优化器在 token 不出现时仍更新它的行，"这可能导致Embedding层过拟合"（[kexue.fm/archives/6869](https://kexue.fm/archives/6869)）；低频 token 的行出现异常，"除Embedding外，其他权重没有这个问题"（[kexue.fm/archives/9736](https://kexue.fm/archives/9736)）；以词为单位的模型"Embedding层参数更多，自然就更容易过拟合"（[kexue.fm/archives/7758](https://kexue.fm/archives/7758)）。
2. 我们的数据：128K 的代价集中在最稀有十分位；稀有输入行干预关掉约一半与 8K 的差距；字节词表没有稀有行。
3. 反证：Kharitonov 的均匀频率控制中，大词表仍记忆更多。所以频率偏斜不是唯一原因（[arXiv html v2](https://arxiv.org/html/2110.02782v2)）。
4. 与机制 A 的关系：在 128K 中，稀有行就是嵌入参数的大部分。现有数据不能区分"嵌入参数作为普通容量"（A）和"稀有行作为专门的钥匙"（B）。

### 4.3 机制 C：序列长度

1. 文献：Kharitonov 通过排除法推测"reduction in the sequences' length"是主因；增加注意力头也提高记忆，作者因此认为注意力是记忆的瓶颈（[arXiv html v2](https://arxiv.org/html/2110.02782v2)）。
2. 我们的数据：同样的文本，字节序列长 4.74 倍。稀有行干预不改变长度，却关掉约一半差距。所以长度最多解释另一半【推断】。
3. 注意：BLT、H-Net 等分块字节模型把主干的序列长度缩短到接近 BPE。如果机制 C 成立，这些模型会失去部分抗重复能力。没有人测过（`byte_level_models.md` Q2）。

### 4.4 机制 D：步数与重复间隔（遗忘）

1. 文献：
   1. Chang 等（NeurIPS 2024）：遗忘与训练步数成幂律；重复数据训练的模型遗忘更快；大 batch 让记忆更不易遗忘（[arXiv 2406.11813](https://arxiv.org/abs/2406.11813)）。
   2. Jagielski 等（ICLR 2023）：早期出现的样本在训练结束时被遗忘；确定性训练的模型不遗忘（[arXiv 2207.00099](https://arxiv.org/abs/2207.00099)）。
   3. Zuo 等 2026：100M 模型，单次出现后的保留差在约 0.15B token 处达到峰值，在 1–5B token 之间衰减到约 0。它是假设，没有种子和 batch 分析（[arXiv html 2607.04969](https://arxiv.org/html/2607.04969)）。
   4. Xu 等 2025：固定 token 数，batch 从 240 降到 60 序列（步数 4 倍），逐字记忆的 Rouge-L 最多降 0.15，主要在出现 32 次以上的序列上（[arXiv html 2505.13171](https://arxiv.org/html/2505.13171)）。
   5. 苏剑林：权重衰减让模型"顶多能记住O(1/λη)步的数据"；多轮训练时让 1/λη 正比于单轮步数（[kexue.fm/archives/11459](https://kexue.fm/archives/11459)）。记忆周期以步计。字节模型每遍走 4.74 倍的步，所以按文本计，它的记忆周期更短【推断】。
2. 我们的数据：128K 用 1.33 倍步数，代价不变；字节每遍换顺序，代价不变（+0.0043）。两者都削弱这个机制，但都没有达到 4.74 倍的步数比。
3. 正在运行的等文本窗口实验直接检验这个机制。

### 4.5 机制 E：字节模型欠拟合，所以对重复不敏感

1. 文献：BLT 与 Efficiency Gap 显示，按 FLOPs 对齐时，字节模型在小预算下落后 BPE（[BLT HTML](https://arxiv.org/html/2412.09871)；[Efficiency Gap HTML](https://arxiv.org/html/2605.12928)）。
2. 我们的数据：在固定文本下，字节的不重复结果（1.3695）好于 128K（1.3828）。所以本设置中的字节模型在不重复文本上并不落后。这削弱"欠拟合"这一解释。
3. 剩下的部分可以归入机制 A：字节模型的 token/参数约为 275，128K 约为 20。2610.05591 的半价遍数公式 R_c ≈ 2.7·(D/N)^0.24 给出字节约 10.4 遍、128K 约 5.5 遍【未验证计算】。

### 4.6 已排除的机制：切分多样性

1. homotokens 和 BPE-dropout 显示，同一文本的不同切分在重度重复下降低代价（[Cosma et al.](https://arxiv.org/html/2601.02867v1)；2610.05591）。
2. 字节只有一种切分。所以这个机制不能解释字节的结果。

## 5. 一个新实验加两个正在运行的实验能拆开这些机制

### 5.1 各实验在各机制下的预测

| 实验 | A：参数/目标 | B：稀有行钥匙 | C：序列长度 | D：步数/遗忘 |
|---|---|---|---|---|
| 1. 等文本窗口（运行中；所有 tokenizer 约 11,444 步） | 字节代价不变（约 0.004） | 不变 | 不变（每文本的 token 数不变） | 字节代价上升，接近 BPE |
| 2. 字节 16/32/64/128 遍（运行中） | 16 遍约 0.018；32 遍约 0.080，约等于 128K 的 8 遍 | 32 遍时仍远低于 0.08 | 上升，但低于同 z 的 BPE | 不确定 |
| 3. 六个 tokenizer 的公式坍缩分析（只需计算） | 六个点落在一条 ΔL–z 曲线上 | 128K、64K 高于曲线 | 小词表低于曲线 | 不区分 |
| 4. 字节 + 128K 输入查找表（新） | 小幅上升，约 0.0075 | 大幅上升，接近 128K | 不变 | 不变 |
| 5. 参数对齐的字节模型（主体约 300M，新） | 约 0.012 | 约 0.004 | 不变 | 不变 |
| 6. 分块字节模型（BLT/H-Net 式，新） | 不变 | 不变 | 上升 | 不确定 |

预测数字都是【未验证计算】，用第 4.1 节的公式；这个公式来自 2610.05591。实验 2 假设字节的 R 遍 run 保持总文本 28.44B 字节和 54,247 步，每遍读 1/R 的文本。在这个假设下，字节大约在 29 遍时达到 128K 8 遍的 z（2.80）。64 遍和 128 遍的 z 超出公式的拟合范围，公式给出的数字没有意义，所以表中不列。

### 5.2 各实验的作用

1. **实验 1（等文本窗口）排除或确认机制 D。** 它让每一步看到相同的文本量，只改变步数。参数、目标、长度、稀有行都不变。若字节代价保持在约 0.005 以下，步数不是原因。
2. **实验 2（字节多遍）检验机制 A 的数量预测。** 若字节在 32 遍时的代价接近 0.08，"字节抗重复"就主要是"每个目标参数少"。若字节在 32 遍时仍远低于 0.08，字节有公式之外的抵抗力，B 或 C 成立。Al-Rfou 的约 230 遍和 dropout 0.55 说明，遍数足够多时字节模型也会过拟合。
3. **实验 3（公式坍缩）不需要训练。** 用每个 tokenizer 的 token 比算出 U 和 N_total，画实测代价对 z。还应比较三种 U 定义：目标数、字节数、信息量。现有三点支持"U = 目标数，N 含嵌入"。这一步决定论文的论点是"字节的特殊性"还是"一条跨 tokenizer 的规律"。
4. **实验 4（字节 + 128K 输入查找表）是区分 A 与 B 的关键实验。** 做法：在每个字节位置，把它所在的 128K token 的输入嵌入加到字节嵌入上（约 98.5M 参数，稀有 token 的行仍然稀有）。目标、长度、步数都是字节的。若代价只升到约 0.0075，嵌入参数只是普通容量（A）。若代价升到接近 128K 的水平，稀有行是专门的记忆钥匙（B）。项目早先的结果是一个提示：Over-Tokenized 式的 n-gram 输入表在重复数据下反转，2.4 遍时比基线差 0.153（[上一轮报告 §2.2](/scratch/gpfs/GROUP/USER/project/marin/docs/della/vocab_survey/reports/重复数据词表过拟合补救调研.md)）。
5. **实验 5（参数对齐的字节模型）补全机制 A。** 现有的 520m 字节点（0.027）是最接近的数据。它的主体参数量本报告没有核对。
6. **实验 6（分块字节模型）是机制 C 唯一干净的检验，但成本最高。** 它把字节目标、无稀有行保留下来，只把主干序列缩短到接近 BPE。建议放在最后。

### 5.3 推荐顺序

1. 先等实验 1 和实验 2 的结果，同时做实验 3（零训练成本）。
2. 若实验 1 显示步数不是原因，而实验 2 跟随公式，做实验 4。
3. 若实验 2 显示字节远低于公式预测，做实验 4 和实验 6，分别检验 B 和 C。

## 结论

空白是真的。但最可能的审稿意见不是"有人做过"，而是"这只是参数量和目标数的差别"。现有三个数据点已经让这条意见有了数字：一条只在 GPT-2 BPE 上拟合的公式，计入嵌入参数、按目标数计 U，就能给出字节约 0.004、128K 约 0.06 的预测。这条公式可能来自项目主人自己的工作，所以它更像论文要检验的对象，而不是论文可以借用的结论。因此，论文最有价值的说法有两种可能的形式。第一种：重复代价是每个不重复目标对应的参数量的函数，与 tokenizer 无关，字节只是这条曲线的最左端。第二种：字节在这条曲线之外还有额外的抵抗力，因为它没有可以充当记忆钥匙的稀有行。

正在运行的两个实验，加上零成本的坍缩分析，可以在不增加训练的情况下决定是哪一种。第一种成立时，论文得到一条跨 tokenizer 的规律，它比"字节抗重复"更一般，也更容易被审稿人接受。第二种成立时，"给字节模型加 128K 输入表"就成为论文的核心因果实验。它也会把项目里的稀有行干预（关掉约一半差距）与字节结果连成一条证据链。无论哪一种，论文中的说法都应限定在测过的范围：8 遍、约 103M 参数的字节模型几乎不损失；520m 时损失 0.027。
