# Mechanisms that set the cost of repeated data (multi-epoch LM training), and which ones favour a byte-level model

Context used for the arithmetic below (from the assignment, not from a source): 300M Qwen3-style model, MuonH, fixed text, 8 passes. Bytes: 54,247 steps; 128K BPE: 11,444 steps; batch 128 x 4096 = 524,288 tokens/step. **Assumption:** these step counts cover the whole 8-pass run, so one pass = ~1,430 steps / ~0.75B tokens for 128K BPE and ~6,781 steps / ~3.56B tokens for bytes. Observed: 128K BPE loses ~0.08 bpb at 8 passes; bytes lose ~0. An earlier run gave 128K 1.33x more steps (smaller batch) and its cost did not change.

Evidence labels: **[direct]** = the source measures the quantity in LM pretraining; **[indirect]** = related setting, theory, or a different quantity; **[inference]** = my reasoning, not in any source.

## Q1. What does "Train Smarter, Not Longer: Memorization-Guided Data Reuse" (arXiv 2607.04969) claim about the interval between repeated exposures?

### Takeaway
The paper defines a "memorization window" tau* = min(tau_ret, tau_gen) measured in **tokens between re-exposures** and hypothesises that reuse is safe when the epoch length N >= tau* and the epoch count E <= E_max; for a 100M model the forgetting (retention) window is 1-5B tokens. The spacing rule is a stated hypothesis, not a validated result; there are no seeds, no batch-size or step analysis, and no full scheduler.

### Cited Findings
- Authors: Zuo, Zeng, Chahed, Velikanov, Rhaiem, Balsebre, Kumar, Belkada, Hacid; submitted 6 Jul 2026; 3rd DATA-FM workshop at ICLR 2026. Abstract: performance "continues to improve with repetition far beyond current practice (e.g., the commonly cited four-epoch limit)"; "a full scheduler remains future work." [direct] — [arXiv abs 2607.04969](https://arxiv.org/abs/2607.04969)
- Definition: "The memorization window characterizes the token interval over which data reuse remains beneficial." tau* = min(tau_ret, tau_gen), tau_ret = when forgetting begins, tau_gen = when overfitting begins. Under spaced repetition "Each sample x_i is re-encountered after exactly N tokens." Three regimes: N < tau* = over-memorization risk; N ~ tau* = "Samples are re-exposed just as they begin to be forgotten"; N > tau* = partial forgetting before re-exposure, effect called "an empirical question." [direct definition, hypothesis] — [arXiv html 2607.04969](https://arxiv.org/html/2607.04969)
- Retention experiment: 100M model, FineWeb, no repetition, 500B tokens at **constant LR**, "rollbacks" from checkpoints at 20-500B tokens. The retention gap Delta R(tau) "peaks at around tau=0.15GT, and then quickly decays to 0"; it "decays substantially between 1 and 5 billion tokens." Rollback trajectories from 20B to 500B "fully overlap", read by the authors as memorization of individual tokens being independent of model capability (fixed architecture/optimizer). [direct] — [arXiv html 2607.04969](https://arxiv.org/html/2607.04969)
- Generalization experiment: 100M model, OpenMathInstruct2 (0.8B unique tokens) plus FineWeb fill, eval MATH500. Epoch sizes N = 0.8/0.85/0.95/1.6/3.2B tokens. Peaks at ~30 epochs (N=0.85B), ~125 (0.95B), ~175 (1.6B). Table 1: tau_ret 1-5B tokens, N* ~ 0.95B, tau_gen >= 1.6B, E_max 125-190 epochs. Adding 6% FineWeb (N=0.85B) "dramatically outperforms" pure HQ (N=0.8B). No error bars or seeds. [direct, single-seed] — [arXiv html 2607.04969](https://arxiv.org/html/2607.04969)
- Batch size and steps are not reported; all budgets are in tokens. The authors call the idea that higher LR shrinks the window "speculative." [direct statement of a gap] — [arXiv html 2607.04969](https://arxiv.org/html/2607.04969)

### Inferences
- [inference] The paper measures the window in tokens at a fixed batch, so tokens and steps are confounded; it cannot say whether forgetting is per token or per optimizer step. Chang et al. 2024 (Q4) measure forgetting as a power law in **steps**.
- [inference] Taken at face value for scale only (100M model, BPE tokens): the 128K run re-sees text every ~0.75B tokens / ~1,430 steps, below the 1-5B-token retention window, i.e. in the "re-exposed before forgotten -> over-memorization" regime; bytes re-see text every ~3.56B tokens / ~6,781 steps, inside the window. This is suggestive only: windows were measured on a different model, tokenizer and LR schedule.
- [inference] The large E_max (125-190) arises with a small high-quality set mixed with fresh web text, a different regime from 8 passes over a fixed general corpus.

### Gaps
- No measured link between spacing and final loss: the paper's own N > tau* case is "an empirical question." No ablation that holds epoch count fixed and only varies spacing.
- No batch size, step count, or LR sweep, so it does not separate steps from tokens.

## Q2. Spacing, forgetting, and memorization capacity (Tirumala 2022, Jagielski 2022, Chang 2024, Morris 2025, Allen-Zhu & Li 3.3, Biderman 2023)

### Takeaway
Forgetting of memorized content is real, gradual and step-driven (power law in steps; faster with duplicated data; slower with larger batch); larger models memorize faster and forget less. Memorization capacity is ~2-3.6 bits per parameter and depends on the number of exposures. The only direct spacing ablation (2610.05591) shows that **consecutive** repeats are very costly (up to +0.46 bpb) while per-epoch shuffled repeats are not; there is no direct study of "4.74x wider spacing at the same number of passes."

### Cited Findings
- Consecutive vs spaced repeats: "replaying shards consecutively raises loss by up to 0.46 bits per byte"; shuffling shards within each epoch changes loss by < 0.01 bpb; "replaying each shard many times in a row is far more costly than revisiting it once per epoch." Consecutive replay also shrinks the unseen-minus-seen gap from 0.10 to 0.005 bpb (511M, R=8) while raising held-out loss, so a small seen/unseen gap is not evidence of good generalization. Concentrating the same repeat count on fewer samples costs +0.004 bpb (45M). [direct; Muon, GPT-2 BPE] — [Xiong, arXiv 2610.05591](https://arxiv.org/html/2610.05591)
- Tirumala et al. 2022: "larger language models memorize training data faster across all settings"; larger models "can memorize a larger portion of the data before over-fitting" and "tend to forget less throughout the training process"; nouns and numbers are memorized first. [direct] — [arXiv 2205.10770](https://arxiv.org/abs/2205.10770)
- Jagielski et al. (ICLR 2023): "examples which appeared early in training are forgotten by the end"; standard image, speech and language models forget over time; nondeterminism is a candidate cause ("deterministically trained models do not forget"); worst-case non-convex models can memorize forever. [direct, privacy framing] — [arXiv 2207.00099](https://arxiv.org/abs/2207.00099)
- Chang et al. (NeurIPS 2024): "a power-law relationship between training steps and forgetting of memorization"; models trained with duplicated data "exhibit faster forgetting"; "training LLMs with larger batch sizes can enhance the models' robustness to forgetting"; knowledge acquisition = small probability gains per exposure, "diluted by subsequent forgetting." [direct, OLMo-based fact injection] — [arXiv 2406.11813](https://arxiv.org/abs/2406.11813)
- Zuo et al. 2026: retention gap after one exposure peaks at ~0.15B tokens and decays to ~0 over 1-5B tokens (100M model). [direct] — [arXiv html 2607.04969](https://arxiv.org/html/2607.04969)
- Morris et al. 2025: "GPT-style models have a capacity of approximately 3.6 bits per parameter"; models "memorize until their capacity fills," then grokking begins and unintended memorization decreases; models 500K-1.5B params. [direct, random/synthetic data plus text] — [arXiv 2505.24832](https://arxiv.org/abs/2505.24832)
- Allen-Zhu & Li (Physics of LMs 3.3): models "can and only can store 2 bits of knowledge per parameter, even when quantized to int8"; "Achieving a 2bit/param capacity requires each knowledge piece to be visited 1000 times"; "With 100 exposures, an undertrained GPT2's capacity ratio falls to 1bit/param." With 7/8 junk data, useful-knowledge capacity drops 20x at 100 exposures (3x/1.5x/1.3x at 300/600/1000 exposures); a special prefix token reduces the loss factor to 2x. [indirect: synthetic biographies] — [arXiv 2404.05405](https://arxiv.org/html/2404.05405)
- Biderman et al. 2023: memorization in Pythia can be forecast from lower-compute trial runs via scaling laws, with "equi-compute recommendations" for recall of such forecasts. [indirect for our question] — [arXiv 2304.11158](https://arxiv.org/abs/2304.11158)

### Inferences
- [inference] Capacity budget: 300M params x 2-3.6 bits = 0.6-1.1 Gbit (~75-135 MB). One pass of the fixed text is ~3.56 GB of raw bytes (from the step arithmetic above), whose information content at ~0.8-1 bpb is ~3 Gbit, i.e. 3-5x more than capacity. So neither model can memorize the corpus outright; the cost comes from partial memorization of the parts the model sees most and stores cheaply. The capacity argument alone does not separate the two tokenizers (same text, same exposures per document), unless parameter count differs (the 128K embedding table; see Q5).
- [inference] Allen-Zhu & Li's capacity rises with exposure count (100 -> 1000). Both tokenizers give each document the same 8 exposures, so exposure count is not the difference; the spacing in steps and the per-token granularity are.
- [inference] If forgetting is a power law in steps (Chang et al.), the byte model's 4.74x more steps between exposures means more decay of each document's memorized trace before it is re-seen, so the repeated passes act more like fresh data. This is the "spacing" mechanism; it is consistent with the direction of the consecutive-replay result (tighter spacing = worse), but nobody has measured the 4.74x-wider-spacing case directly.

### Gaps
- No source measures loss cost as a function of spacing at a fixed pass count across a range of spacings (only consecutive vs per-epoch).
- Tirumala and Jagielski give no forgetting numbers on the abstract pages I read; the full papers have curves I did not extract.
- No source measures forgetting rate per step vs per token separately.

## Q3. Multi-epoch studies and regularization (Hernandez 2022, Xue 2023, Muennighoff 2023, 2025-2026 work)

### Takeaway
Up to ~4 epochs costs little, value decays with ~15 repetitions as the 1/e scale (Muennighoff). The 2026 Muon-based study fits the excess loss as Delta L = 0.0203 bpb x z^1.07 with z = (R-1) N / U, U = unique **target tokens**: cost grows with params per unique token, not with steps. Damage peaks at intermediate repeat counts (Hernandez; Chudnovsky 2026). Weight decay far above 0.1 (up to 30x) and dropout reduce repetition cost; bigger models overfit sooner.

### Cited Findings
- Hernandez et al. 2022: an 800M model degrades to the level of a 400M model when "repeating 0.1% of the data 100 times" (rest unique); "a strong double descent phenomenon"; a predictable middle range of repetition does disproportionate damage, hypothesised as "a range in the middle where the data can be memorized"; repetition damages copying and induction heads. [direct] — [arXiv 2205.10487](https://arxiv.org/abs/2205.10487)
- Chudnovsky et al. 2026 ("Internal Data Repetition Destroys Language Models"): at fixed compute, eval loss peaks at an intermediate repeat count; "repeating a moderately sized subset a moderate number of times damages performance more than repeating a large subset"; the peak location is "well-fit by a power law in model size"; example: Qwen3-style 344M model on FineWeb-Edu-Dedup; when repeats take 10% of FLOPs, the worst repeat count equals a no-repetition run with 67% of the FLOPs. [direct; model family close to ours] — [arXiv 2606.24998](https://arxiv.org/abs/2606.24998)
- Muennighoff et al.: "training with up to 4 epochs of repeated data yields negligible changes to loss compared to having unique data"; R*_D = 15.39 ("15 repetitions (or 16 epochs)"; repeated tokens lose 1/e of value), R*_N = 5.31; "Meaningful gains from repeating data can be made up to around 16 epochs"; 400 runs, up to 9B params / 900B tokens. [direct] — [arXiv 2305.16264](https://arxiv.org/html/2305.16264)
- Xiong 2026 ("What Is a Repeated Token Worth?"; Muon for matrices + Adam; no weight decay, no dropout; GPT-2 byte-level BPE, 50,257 vocab; 23M-361M main grid, 14M-2B fixed-U sweep): second epoch worth 0.87-1.02 of a fresh token; critical epoch (repeat worth 1/2 fresh) R_c ~ 2.7 (D/N)^0.24, "about four to five up to a TPP of 20," ~10 at 300 TPP; excess loss over fresh data at equal compute Delta L = A z^p, z = (R-1) N_total / U, A = 0.0203 bpb, p = 1.07 (R^2 = 0.96); U = unique training **targets**; counting embedding parameters in N "removes the size term"; batch sizes 131K-1M tokens with steps K = D/B (no separate batch sweep reported in the parts I read); a re-tokenization study uses BPE-dropout (p=0.05). Cites Lovelace et al. 2026 for weight decay lowering repetition cost. [direct] — [arXiv 2610.05591](https://arxiv.org/html/2610.05591)
- Xue et al. (NeurIPS 2023): "the model is susceptible to overfitting, leading to multi-epoch degradation"; dataset size, model size and objective matter; most regularizers did not help except dropout, which "requires careful tuning when scaling up"; "larger models are more susceptible to overfitting under token-crisis conditions"; 2^27 tokens x 2^8 repeats overfits while 2^29 tokens does not; dropout 0.2-0.3 best in the MoE sweep; weight decay "can even make the training process unstable" (their T5/Adafactor setup). [direct] — [arXiv 2305.13230](https://arxiv.org/html/2305.13230)
- Xu, Wu, Cho, Hu, Wang 2026: DCLM 100M unique tokens, 72M-1.4B models, AdamW: "the optimal weight decay is consistently much larger than the standard value of 0.1"; tuned WD rises from 0.4 (72M) to 3.2 (1.4B); at 257M, loss 3.88 (WD 0.1) -> 3.42 (strong WD); weakly regularized runs show "repeated-epoch collapse"; "larger models prefer fewer epochs and stronger weight decay"; batch size fixed at 128 (not studied). [direct] — [arXiv 2606.06888](https://arxiv.org/html/2606.06888v1)
- Kim, Kotha, Liang, Hashimoto 2025: optimal weight decay "30x larger than standard practice"; with epoching + regularization + parameter scaling + ensembling, "5.17x less data than our baseline" at 200M tokens; distillation into an 8x smaller model keeps 83% of the ensemble gain. [direct] — [arXiv 2509.14786](https://arxiv.org/abs/2509.14786)
- Yan et al. 2025/2026 (theory, SGD on linear regression): effective reuse E(K,N) ~ K for small K ("every new epoch yields a linear gain"), plateau Theta(log N) for strongly convex problems: "Larger datasets can be repeated more." [indirect, theory] — [arXiv 2511.13421](https://arxiv.org/abs/2511.13421)
- Muon-specific: Muon beats Adam mainly through associative-memory parameters (attention V/O and FFN) and learns **tail** classes of heavy-tailed data better, via a more isotropic update spectrum (ICLR 2026). [indirect; relevant because the run uses MuonH] — [arXiv 2509.26030](https://arxiv.org/pdf/2509.26030)

### Inferences
- [inference, quantitative check] Plugging our numbers into Xiong's law (fitted on GPT-2 BPE with Muon; extrapolation to other tokenizers is untested): R = 8, U per pass = 0.75B BPE tokens or 3.56B byte tokens.
  - 128K BPE, N = 0.30B: z = 7 x 0.30 / 0.75 = 2.8 -> Delta L ~ 0.061 bpb. If N_total includes a ~0.13B tied 128K x 1024 embedding (d_model is an assumption): z ~ 4.05 -> ~0.091 bpb. Both bracket the observed ~0.08 bpb.
  - Bytes, N ~ 0.30B: z = 7 x 0.30 / 3.56 = 0.59 -> Delta L ~ 0.012 bpb, close to "nothing lost" at typical seed noise.
  - So the existing law already predicts a ~5-8x smaller cost for bytes, entirely because U counts **targets** (tokens) and bytes have 4.74x more targets per text, plus fewer embedding parameters. Whether U should count tokens, bytes of text, or information is exactly what this law cannot tell, because it was fitted with one tokenizer; a byte-vs-BPE run at fixed text is the test that separates "more prediction targets per text" from "same information."
- [inference] The embedding table is the cleanest tokenizer-specific capacity lever: a 128K vocabulary adds ~10^8 parameters that act as a lookup memory (Xiong: counting embeddings collapses the size term; Kharitonov: memorization shifts away from attention when sequences shorten). The byte model has ~0.26K x d embedding parameters, essentially none.
- [inference] Dropout, larger weight decay and Muon's tail learning are recipe levers, equal across the two tokenizers in our runs; they matter for the absolute cost, not the gap, unless MuonH's tail learning interacts with the 128K vocabulary's long tail of rare tokens (rare-token rows are touched only when the token appears and are easy to memorize). Untested.

### Gaps
- Lovelace et al. 2026 (weight decay lowers repetition cost) is cited inside 2610.05591; I did not locate and verify the paper itself.
- Muennighoff's regularization results (dropout, filtering) were not in the page parts I read.
- No multi-epoch study I found varies the tokenizer.

## Q4. Batch size, steps per epoch and learning rate in multi-epoch training

### Takeaway
Three sources point the same way: at fixed tokens, smaller batches (more steps) reduce verbatim memorization (Xu et al. 2025, 4x step range) and multi-epoch overfitting (Xue et al., qualitative), while larger batches make memorized content more robust to forgetting (Chang et al.). None varies steps per epoch at fixed batch and fixed text, and none reaches the 4.74x step ratio with equal tokens; the effect sizes reported are modest, consistent with the null at 1.33x.

### Cited Findings
- Xu, Solergibert i Llaquet, Bosselut, Schlag 2025 ("Positional Fragility"; 1B/3B/8B on 83B tokens with controlled-frequency book data): global batch 60/120/180/240 sequences (0.5M-2M tokens) at fixed total tokens = 170,005 / 85,002 / 56,668 / 42,501 steps. Verbatim memorization (Rouge-L) "increases most significantly for sequences seen more than 32 times"; the smallest-vs-largest-batch gap "reaches up to 0.15 in Rouge-L score at high repetition frequencies"; smaller batches "reduce exact memorization while preserving language quality." Validation perplexity 18.71 (60 GBS) vs 22.86 (240 GBS). The caption's "approximately 90 fewer tokens" does not match 0.15 x 500 = 75 (internal inconsistency). [direct, but memorization not held-out loss, and confounded with general undertraining at large batch] — [arXiv html 2505.13171](https://arxiv.org/html/2505.13171)
- Xue et al. 2023, Appendix L.1: "Empirically, larger batch size is easier to overfit, and smaller batch size can usually reduce overfitting"; "when using smaller batch size ... model still has little multi-epoch degradation" (qualitative; no numbers given). [direct, qualitative] — [arXiv html 2305.13230](https://arxiv.org/html/2305.13230)
- Chang et al. 2024: forgetting follows a power law in training **steps**; "larger batch sizes can enhance the models' robustness to forgetting"; dedup and larger batch help factual acquisition (search-snippet detail: their reduced-batch run cut batch 16x, 2048 -> 128; not verified from the full text). [direct] — [arXiv 2406.11813](https://arxiv.org/abs/2406.11813)
- Zuo et al. 2026 do not report batch size or steps; they flag LR effects on the window as speculative. [gap statement] — [arXiv html 2607.04969](https://arxiv.org/html/2607.04969)
- Xiong 2026: batches fixed per model size (131K-1M tokens), steps K = D/B, constant LR with final linear warmdown; no separate batch sweep in the parts I read. [direct for recipe only] — [arXiv html 2610.05591](https://arxiv.org/html/2610.05591)
- Xu et al. 2026 fix batch at 128; tuned LRs for strongly regularized runs 1e-3 to 1e-2; no LR-overfitting ablation. [direct for recipe only] — [arXiv html 2606.06888](https://arxiv.org/html/2606.06888v1)

### Inferences
- [inference] Two step-related mechanisms predict bytes gain from more steps per pass: (1) more noisy updates between exposures -> more forgetting (Chang power law; Jagielski: nondeterminism drives forgetting); (2) smaller effective per-document gradient share per step (a document's tokens are spread over more steps), similar to the small-batch effect in Xu et al. 2025. The 1.33x-step experiment on 128K changed nothing; Xu et al. needed a 4x step range to see a 0.15 Rouge-L gap concentrated at > 32 repeats, and at 8 passes we are far below 32 repeats. So the null at 1.33x does not rule out the step mechanism at 4.74x, but it suggests it is weak at 8 passes; the U-in-targets / embedding-capacity mechanisms (Q3, Q5) predict the observed size without any step term.
- [inference] The running experiment that equalizes text per window and step count across tokenizers is the right control: if the byte advantage survives equal steps, steps/spacing are not the cause; if it vanishes, they are.

### Gaps
- No source varies steps per epoch while holding batch, text and passes fixed.
- No source tests LR (or MuonH-style normalized updates) against repetition cost; the LR effect on the memorization window is called speculative.

## Q5. Tokenizer-specific mechanisms: why a byte vocabulary may lose nothing at 8 passes while 128K BPE loses 0.08 bpb

### Takeaway
One direct source (Kharitonov et al. 2021) shows larger BPE vocabularies memorize more at a fixed parameter count, and attributes it to **shorter sequences**, after ruling out compression, vocabulary growth and token frequency. Combined with the repetition law that scales cost with (R-1) N / U in tokens and with embedding parameters counting toward N, the most supported explanations are: more prediction targets per text, longer sequences that make memorization harder, and the absence of a large embedding lookup memory. Spacing/steps is plausible but less supported.

### Cited Findings
- Kharitonov, Baroni, Hupkes 2021: BPE vocabulary size "greatly affects both ability and tendency" to memorize; larger vocab -> better fitting of random labels (encoder ~87% at 611 tokens to > 98% at 18,336), monotonically higher membership-inference AUC, more training-data recovery on PAQ; holds with parameters held fixed (~18.2M SNLI LM/MLM; ~24.4M and ~162M QA). Conjecture: "this effect is caused by reduction in the sequences' length that happens as the BPE vocabulary grows." Controls: the trend persists on incompressible random bit strings (not compression); doubling vocab at fixed length gives a different curve, so "cannot be explained solely by the vocabulary growth"; a uniform-frequency construction keeps the effect (not frequency); more attention heads improve memorization (attention as bottleneck). Length is supported by elimination, not by a direct test. [direct, small models, vocab 611-20,776, not bytes and not 128K] — [ar5iv 2110.02782](https://ar5iv.labs.arxiv.org/html/2110.02782); [arXiv abs](https://arxiv.org/abs/2110.02782)
- Xiong 2026: counting embedding parameters in N (N_total) "removes the size term" in the repetition-cost fit, i.e. embedding parameters behave like capacity for overfitting repeated data. [direct, one tokenizer] — [arXiv html 2610.05591](https://arxiv.org/html/2610.05591)
- Xiong 2026: excess cost scales with z = (R-1) N / U where U counts unique training targets. [direct, one tokenizer] — [arXiv html 2610.05591](https://arxiv.org/html/2610.05591)
- Yan et al.: larger datasets (more samples) can be repeated more before returns vanish. [indirect, theory] — [arXiv 2511.13421](https://arxiv.org/abs/2511.13421)
- Allen-Zhu & Li: capacity grows with exposure count and drops sharply with junk data. [indirect] — [arXiv 2404.05405](https://arxiv.org/html/2404.05405)

### Inferences
Ranked candidate mechanisms for "bytes lose ~0, 128K loses 0.08 bpb at 8 passes" (all [inference]):
1. **More targets per text (U in tokens).** Xiong's law, with U counted in tokens, predicts ~0.06-0.09 bpb for 128K and ~0.01 bpb for bytes at our sizes (Q3). Each byte target is low-information and highly predictable from local context, so per-target memorization gains less. Testable: the running equal-text-per-window experiment does not change U; a byte model with fewer passes over more text would.
2. **Sequence length / memorization difficulty (Kharitonov).** At 4096 context, bytes cover ~4.74x less text per window; each memorized span must be reproduced over ~4.74x more positions, and attention must carry it. Kharitonov's controls point to length, not vocab size or frequency, as the driver.
3. **Embedding lookup capacity.** A 128K table adds ~10^8 parameters (d_model-dependent) that store per-token statistics, including rare tokens touched only by a few documents; counting them in N_total explains Xiong's size term. Bytes have no such table. Testable: freeze or shrink the 128K embedding (or tie and low-rank it) and see whether the repetition cost drops.
4. **Spacing in steps (forgetting between exposures).** 4.74x more steps between re-exposures -> more power-law forgetting (Chang), and a re-exposure interval inside/after the retention window instead of before it (Zuo). Supported in direction only; the 1.33x null suggests a weak effect at small ratios. The running step-equalized experiment isolates this one.
5. **Smaller per-step share of each document (batch effect).** Same document spread over more updates resembles small-batch training, which reduces verbatim memorization (Xu et al. 2025) and overfitting (Xue et al.). Only a 4x step range has been tested, at > 32 repeats.

### Gaps
- No study compares byte-level and BPE models under multi-epoch training at fixed text; a dedicated search ("byte-level vs BPE memorization repeated data") found none.
- Kharitonov's vocab range (611-20,776) does not reach bytes (256) or 128K, and models are small (18M-162M).
- Xiong's law is fitted with one tokenizer (GPT-2 BPE); whether U should be tokens, bytes or bits of information is untested, so the quantitative check above is an extrapolation.
- Assumption to verify with the project owner: the step counts (54,247 / 11,444) cover all 8 passes; the 128K model's d_model and tied/untied embedding (needed for N_total).
