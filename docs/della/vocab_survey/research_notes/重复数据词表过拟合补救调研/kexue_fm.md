# kexue.fm（苏剑林，科学空间）中可用于缩小"重复数据词表代价"的思路

范围说明：
1. 来源只有本地 kexue.fm SQLite 全站库（`kexue-fm:kexue` skill，2026-10-21 查询）。共检索约 15 路中英关键词，精读 35 篇文章。
2. 每节 "Cited Findings" 只写文章本身的主张。"Inferences" 写我对本目标（300m MuonH Qwen3，8 遍 1/8 子集，6 种词表）的外推。
3. 栈事实（不是来自 kexue.fm，而是读本仓库代码）：`lib/levanter/src/levanter/optim/muonh.py` 默认 `beta1=0.9, beta2=0.95, epsilon=1e-8`；输入 Embedding 走 `optax.scale_by_adam`，无权重衰减；lm_head 走 `scale_by_adamh`；`util.norm_preserving_update` 对二维参数保持**整个矩阵**的 Frobenius 范数不变（不是逐行）。speedrun 配置可能覆盖这些默认值，使用前要核对。

## 问题 1：kexue.fm 对"为什么重复数据有害、最优轮数是多少"说了什么？

### Takeaway
kexue.fm 没有专门做多轮 LLM 预训练实验的文章。只有两篇给出理论框架：一篇把 Multi-Epoch 代价写成幂律惩罚项并推出最优轮数（11833），一篇把权重衰减看成对训练数据的滑动平均记忆，并明确建议多轮训练时让记忆周期 1/(λη) 正比于单轮步数（11459）。

### Cited Findings
- 苏剑林把测试损失分解为"数据误差 + 优化误差 + 架构误差"。他用 K 表示学过的样本数，用 D 表示训练集大小，K/D 即轮数。他假设数据误差为 α9·D^(-γ9) + α10·(K/D)^γ10，第二项是对 Multi-Epoch 过拟合的惩罚。—— [解构Scaling Law：优化、架构、数据的三重奏（2026-07-29）](https://kexue.fm/archives/11833)
- 同文用"异幂不等式"推出最优样本数 K* ∝ D^(γ10/(γ̂1+γ10))，得到"数据越少，越应该训更多轮"。他指出这与 2511.13421 的结论相反，并提出推广形式 α10·K^γ10·D^(-γ11)，使最优轮数随 D 增减都可能。他也承认该项在 K→∞ 时发散，不合理，只适合小范围拟合。—— [11833](https://kexue.fm/archives/11833)
- 同文转述《Prescriptive Scaling Laws for Data Constrained Training》（2605.01640）：用 K/D−1 代替 K/D，并让 α10 与参数量 N 正相关，即"参数越多越容易过拟合，越不应该多轮训练"。—— [11833](https://kexue.fm/archives/11833)
- 同文"记忆之层"一节：PKM、UltraMem、Over-Encoding、Engram 等稀疏 Memory 层可以看成"没有计算的可训练向量"，按 Router 或 N-gram Hash 激活，相当于 MoE 的极端情形；它们的 Scaling Law 应与 MoE 类似。他还指出 Embedding 是否计入参数量 N 在小规模下会造成明显偏差。—— [11833](https://kexue.fm/archives/11833)
- 苏剑林把带权重衰减的更新写成 θ_t = (1−λη)θ_{t−1} + λη(−u_t/λ)，即参数是更新量的 EMA。模型最多记住 O(1/(λη)) 步的数据（"记忆周期"）。λ=0 时记忆周期无限，但初始化无法被遗忘，且 AdamW 的 Weight RMS 会以 η√t 膨胀。他的建议原文是："比较适合的设置是让 1/λη 正比于训练步数，如果是Multi-Epoch的训练场景，则考虑让 1/λη 正比于单个Epoch的训练步数。"—— [滑动平均视角下的权重衰减和学习率（2025-12-05）](https://kexue.fm/archives/11459)
- 同文推出常数 WD 下"每个 batch 等权"的最优学习率调度 η_s ≈ η_max/(λη_max·s+1)，以及 λ_s = αη_s 时 η_s ≈ η_max/√(2λ_max·η_max·s+1)。—— [11459](https://kexue.fm/archives/11459)
- 苏剑林认为 Scaling Law 的指数由问题本身决定，工程改进只改系数。—— [11833](https://kexue.fm/archives/11833)

### Inferences
- 1a（解释层面）：11833 的"记忆之层"视角支持已观测现象。输入 Embedding 的每一行是一个只在该 token 出现时激活的"稀疏专家"。128K 词表的稀有行，每个参数分到的训练出现次数远少于 8K 词表。若 2605.01640 的"α10 随参数量增大"成立，按"每次激活的有效参数"计算，128K 的过拟合项系数更大。这与 0.082 vs 0.026 bpb 的 3 倍差距方向一致。这只是解释，不是证据。可检验的预测：把 repetition cost 对"每个词表的稀有行平均出现次数"作图，应近似单调。
- 1b（可测试方案："输入 Embedding 加记忆周期等于单轮的权重衰减"）：
  - 是什么：给目前无 WD 的输入 Embedding 加解耦权重衰减，取 λ·η_adam ≈ 1/(单轮步数) = 8/T。
  - 为什么可能有用：无 WD 时 Embedding 的记忆周期无限，8 遍重复会把同一组上下文的梯度方向累加 8 次。WD 让某一行最多"记住"约一轮的更新。对一个每轮只出现一次的稀有 token，两次出现之间该行衰减约 e^(−1)。所以第 8 遍的推动不会叠加在前 7 遍完整保留的方向上。这直接针对"记忆在方向上"的观测。
  - 怎么实现：`muonh.py` 的 `adam_transform` 在 `scale_by_adam` 之后加 `optax.add_decayed_weights(λ, mask=embedding_mask)`，再乘 `-adam_lr`。只作用于输入 Embedding。可以只扫 λ 一个参数（3 个值：记忆周期 = 0.5、1、2 轮）。
  - 风险：(1) 所有行都会衰减，稀有行整体变小，第一层看到的输入幅度变化；Qwen3 是 pre-norm，所以只影响残差流中 Embedding 的相对占比，风险中等。(2) 主人已观测"稀有行范数不随重复增长"，所以 WD 的作用应该来自方向遗忘，而不是控制范数；若 cost 不变，说明记忆不在"累加"而在"拟合"。(3) 苏剑林的结论针对单轮预训练的遗忘问题，"多轮时正比于单轮步数"是他的一句建议，文中没有实验。
- 1c：11833 的最优轮数公式在本目标里没有直接用处，因为本目标固定 8 遍。它只说明一个可测量：在 1/8 子集上用 2、4、8 遍画 cost(K/D) 曲线，可以估计每个词表的 γ10，并检查"128K 的 α10 更大但 γ10 相同"这一假设（苏剑林的"指数普适、系数可变"观点）。

### Gaps
- kexue.fm 没有任何文章报告 LLM 多轮训练的实测数字，也没有讨论"重复伤害稀有 token"或"词表大小与过拟合"。
- 11459 的记忆周期分析假设"每一步梯度只含当前 batch 信息"，没有考虑同一数据被重复看到的情形。

## 问题 2：kexue.fm 对 Embedding 层、稀有 token、词表大小说了什么？

### Takeaway
最相关的发现是"动量优化器会过度更新稀有 token 的 Embedding"（LazyOptimizer，6869；Lion/Tiger 异常，9736）。苏剑林的对策是"只在 token 出现时才更新该行"（Lazy 化），或者用 Tied Embedding 让梯度不再稀疏。我按本栈默认超参计算，Adam 下一次出现带来的累计更新约是"只更新一步"的 13 倍，而且全部朝同一个上下文梯度的方向。这是本次调研中最便宜、最直接针对"方向记忆"的候选方案。

### Cited Findings
- LazyOptimizer：所有带动量的优化器（含 Adam、SGDM）都有一个问题。一个词被采样过后，动量不为 0；之后它不在 batch 里时梯度为 0，但仍用历史动量更新，"就算没有被反复采样的词，对应的Embedding也被反复更新了，就导致了过拟合"。对策是只有当该词被采样过才更新。他的实现用"该行梯度是否为 0"判断是否出现；他的版本对未出现的词仍更新动量缓存，只不更新参数，并说"有评测说这样做其实效果会更好些"。IMDB LSTM 例子中，验证准确率从约 83.7% 提高到 84.9% 以上。—— [Keras实现两个优化器：Lookahead和LazyOptimizer（2019-07-30）](https://kexue.fm/archives/6869)
- 同文：Lookahead = 每 k 步把权重向 k 步前的备份插值 θ ← θ + α(θ̃ − θ)。—— [6869](https://kexue.fm/archives/6869)
- 苏剑林在 7B 预训练中用 Tiger 优化器，发现部分低频 token 的 Embedding 分量达到 ±100，其他权重没有这个问题，训练 loss 正常。原因：低频 token 的动量长期不为 0；sign 优化器的更新量不随动量衰减；"一个token的Embedding由于过度更新偏向了某个方向之后，它的梯度可能会适应并助长这种变化"；与权重衰减 λ=0.01 平衡于 ±1/λ = ±100。他认为 Adam 中该问题"可能不会有明显感知"，因为 Adam 更新量随动量指数下降。—— [Lion/Tiger优化器训练下的Embedding异常和对策（2023-08-28）](https://kexue.fm/archives/9736)
- 同文给出三种对策：(1) Embedding 更新 Lazy 化；(2) 用 Tied Embedding 让整个 Embedding 矩阵都有非零梯度，他"使用将模型特征的channels对半交换的Tied Embedding，能解决以上问题，并且效果似乎比Untied Embedding还要好一点"；(3) Lion 作者的做法：Embedding 层用 Adam，其他层用 Lion。他还提醒：低频 token 的 Embedding 质量影响多语种能力和后续微调，这种能力"在Loss体现不出来"。—— [9736](https://kexue.fm/archives/9736)
- Tied Embedding 在残差分支初始化接近 0 时，初始损失约为 log(e^(dσ) + n−1)，远大于 log n。对策：初始化标准差取 σ = (log n)/d，或者不共享，或者在最后 Normalization 之后加一个正交初始化的投影（BERT 的做法）。—— [语言模型输出端共享Embedding的重新探索（2023-07-20）](https://kexue.fm/archives/9698)
- 大词表的缺点：割裂 token 之间在字符层面的联系，"可能会影响泛化"，例如模型不知道"太阳能"由"太""阳""能"组成。—— [大词表语言模型在续写任务上的一个问题及对策（2023-09-13）](https://kexue.fm/archives/9762)
- 在苏剑林自己的词向量模型中，高频而互信息小的词（停用词）模长接近 0，模长近似 ICF（−log P(w)）；"如果通过调整模长就能达到的，模型自然会选择调整模长而不是拼死拼活调整方向"。—— [更别致的词向量模型(五)：有趣的结果（2017-11-19）](https://kexue.fm/archives/4677)

### Inferences
- 2a（定量补充，是我的计算，不是文章主张）：设某 token 第一次出现，此前该行 m=v=0，β1=0.9，β2=0.95，训练后期偏差修正≈1。出现后第 k 步，Adam 的逐元素更新为 (1−β1)/√(1−β2)·(β1/√β2)^k·sign(g) = 0.447·0.923^k·sign(g)。累计约 0.447/(1−0.923) ≈ 5.8 个学习率单位，而且所有分量都朝这一次梯度的符号方向。Lazy 版只走第一步 0.447。所以非 Lazy 的 Adam 对"只出现一次"的稀有 token，等于把那一个上下文的梯度方向放大约 13 倍；β2=0.999 时放大约 10 倍（首步 3.16，累计约 32）。高频 token 每步都出现，梯度方向互相平均，没有这个放大。8 遍重复时，同一上下文每遍再推一次，方向一致。这与"稀有行范数不变、方向被记住"的观测相容（范数受 Adam 单步上限约束，方向被反复放大）。苏剑林在 9736 中说 Adam 下"可能不会有明显感知"，我的计算显示累计放大并不小，这一点要用实验判断。
- 2b（可测试方案："Lazy Adam 只用于输入 Embedding"）：
  - 是什么：输入 Embedding 中，梯度全为 0 的行本步更新置 0。按苏剑林的变体，动量和二阶矩照常衰减（也可试标准 Lazy：未出现行的 m、v 也冻结）。
  - 为什么可能有用：它去掉了 2a 中约 13 倍的方向放大。对所有词表都适用；词表越大，稀有行越多，作用越大，正好与 cost 随词表增大的方向一致。256 字节词表几乎每行每步都出现，因此几乎不受影响，可作为负对照。
  - 怎么实现：在 `adam_transform` 中，对 Embedding 参数，`mask = any(grad != 0, axis=-1, keepdims=True)`，`update = update * mask`。注意 `clip_by_global_norm` 之后梯度仍保持零行。约 10 行代码，零额外计算。同时测"标准 Lazy"（m、v 也只在出现时更新）两个变体。
  - 风险：(1) 有效学习率对稀有行下降，unique 数据的基线也可能变化；但目标是让重复 run 追上未改动的 unique 基线，所以只需在重复 run 上加。(2) 2a 的放大在 unique 数据上同样存在，若 Lazy 也改善 unique 基线，cost 的"缩小"需要用"同一改动下 unique vs 重复"重新定义，要同时跑两种 run。(3) 若 Marin 实际 β1、β2 与默认值不同，放大倍数要重算。
- 2c（可测试方案："按出现频率缩放 Embedding 行学习率"）：苏剑林在 11647 推出 Embedding 的最速下降是逐行 RMS 归一化的 SGD，即每个出现的行步长相同、与出现次数无关（见问题 3）。这意味着每次出现的步长对稀有行最大。方案：每行学习率乘 min(1, (c_i/c_ref)^α)，c_i 为该行在训练子集中的出现次数，α ∈ {0.25, 0.5}。风险：稀有行学习不足，unique 部分的学习也变慢；需要扫 c_ref。
- 2d（可测试方案："稀有行的输入/输出部分共享"）：9736 说 Tied Embedding 让稀疏梯度变稠密，苏剑林还报告"对半交换 channels"的 Tied 版本略好于 Untied。本栈中输入用 Adam、lm_head 用 AdamH，完全 Tie 会改变优化器组，代价大。较小的版本：只对稀有行（如 rank > 8K）把输入行参数化为 lm_head 对应列（经对半交换 channels 或一个固定正交投影）加一个小的自由残差。为什么可能有用：稀有 token 作为输入和作为目标的出现次数合并，每行有效数据翻倍；输出侧每步都有梯度，方向不再只由少数输入上下文决定。风险：高；9698 指出 Tie 引起的初始损失问题；lm_head 的整体范数约束会把输入行也绑住。建议排在 2b、1b 之后。
- 2e：4677 的观察（模长编码频率或"重要性"）提示：本栈 lm_head 用整体 Frobenius 范数约束，行之间可以重新分配范数，所以频率仍可放在行范数里；但输入行的 Adam 无约束。若诊断发现稀有输出行的范数被用来编码先验，问题 4 的 logit adjustment 可以把这部分功能拿走。

### Gaps
- 没有文章讨论 Adam 下稀有 Embedding 过度更新的定量规模；2a 是我的推算。
- 没有文章给出 Embedding 学习率或 WD 随词表大小、token 频率变化的规则；MuP 系列只讨论随宽度 d 的缩放。
- 没有文章讨论用子词向量组合（如 8K 片段均值）初始化或替换稀有 token 行；主人现有的最佳方案在 kexue.fm 中没有先例。

## 问题 3：Muon、超球面优化、权重衰减与 MuP 系列对 Embedding 和 lm_head 有何启示？

### Takeaway
苏剑林明确主张 Embedding 和 LM Head 不用 Muon。他从"稳定性指标"推出：Embedding 的最速下降是逐行 RMS 归一化 SGD，LM Head 是逐列归一化 SGD；参数约束可以用"事后裁剪（Post Clip）"或"事前衰减（Pre Decay）"实现，普通 WD 就是 RMS 范数下的 Pre Decay。这些都是稳定性推导，不涉及泛化或重复数据；对本目标的价值主要是给出"按行约束"的实现模板。

### Cited Findings
- Muon 只适用于"稠密输入的线性层的矩阵参数"；Embedding 层和最后的分类层（含 LM Head）不能用 Muon，"否则效果会明显差"；用 Adam 即可。Embedding 可视为多个 (1,d) 矩阵分别做 msign，结果是 Normalized SGDM。—— [Muon优化器指南：快速上手与关键细节（2025-11-19）](https://kexue.fm/archives/11416)
- 输入和输出 Embedding "虽然也是矩阵，但它们使用上是稀疏的，所以更合理的方式也是将它们当成多个向量独立处理"。—— [Muon优化器赏析：从向量到矩阵的本质跨越（2024-12-10）](https://kexue.fm/archives/10592)
- Embedding 层的前向与更新稳定性指标是最大行 RMS，最速下降为 ΔE_i = −η·G_i/‖G_i‖_RMS（逐行 RMS Norm，Normalized SGD）。LM Head 的三个稳定性指标也是最大行/列范数，最速下降为逐列 Normalized SGD；LM Head 初始化标准差与学习率按 Θ(1/d) 缩放，Embedding 按 Θ(1)。这与 Scion 一致。—— [MuP之上：3. 特殊情况特殊处理（2026-03-02）](https://kexue.fm/archives/11647)
- 保持参数范数 ≤ τ 有两种方案。Post Clip：每步更新后投影回范数球。Pre Decay：先把参数范数降到 (1−η) 倍再更新，可证明只要初始化满足 ‖ω_0‖ ≤ τ，就始终 ‖ω_t‖ ≤ τ；RMS 范数下的 Pre Decay 就是普通权重衰减。对 Embedding，裁剪算子是"将每行向量的 RMS 都裁剪到不超过 τ"；LM Head 按列。他的观点是"只需保证‖ω‖ = O(τ)"，不必像 Hyperball、Nemotron-Flash 那样严格固定范数，因为固定范数"会破坏原本的训练动力学"。—— [MuP之上：4. 坚守参数的稳定性（2026-04-24）](https://kexue.fm/archives/11729)
- 超球面上的 SGD 最速下降方向为切向投影 φ = (g − ⟨g,w⟩w)/‖g − ⟨g,w⟩w‖。—— [流形上的最速下降：1. SGD + 超球面（2025-08-01）](https://kexue.fm/archives/11196)
- Lion 论文作者认为 sign 引入的噪声让模型进入更平坦的区域；苏剑林认为这只证明了 Lion 进入更平坦区域，不能证明是 sign 造成的，他自己的猜测是 sign 平等对待每个分量。—— [Google新搜出的优化器Lion（2023-02-16）](https://kexue.fm/archives/9473)

### Inferences
- 3a：11647 的推导说明"逐行归一化"是 Embedding 的"正确"几何。它让每个出现的行每步走相同步长，与出现次数无关。对稳定性这是对的；对泛化，这正好让稀有行"每次出现"的步长最大。这是 2c（按频率缩放）的理论动机：稳定性只约束最大行，不要求所有行同步长，所以按频率降低稀有行步长不违反苏剑林的稳定性条件。
- 3b（可测试方案："只对稀有行做 Post Clip 或逐行超球面"）：主人已观测稀有行范数不增长，所以行范数裁剪大概率不触发，预期无效。我不建议优先测。若要测，按 11729 的逐行 RMS 裁剪实现最简单（`E = E * min(1, τ/rms(E_i))`）。
- 3c：本栈 lm_head 的 AdamH 只固定整个矩阵的 Frobenius 范数。按 11647 的观点，LM Head 的自然几何是逐列（逐 token）约束。把 AdamH 改为"逐 token 行保持范数"会让稀有输出行不能靠范数编码低先验，只能靠方向，可能加重方向记忆；反方向（保持现状）则允许范数承担频率信息。这是推测，不建议作为首批实验，但在诊断"输出行代价"时值得记录稀有输出行的范数随重复如何变化。
- 3d：11459 的 EMA 视角也适用于 MuonH/AdamH：固定范数的球面更新等价于一个隐式衰减，其"记忆周期"约为 ‖W‖/(η·‖u‖) 的量级。对 lm_head 而言，这个记忆周期由学习率决定，而不是由 WD 决定。若想测 1b 的思路在 lm_head 上的版本，需要调 lm_head 的 AdamH 学习率或调度，而不是加 WD。这是我的推断，文章没有讨论超球面上的记忆周期。

### Gaps
- MuP 系列与流形系列全部是"稳定性"或"最速下降"推导，没有关于过拟合、重复数据或稀有 token 的实验。
- 没有文章讨论 Muon 与 Adam 在多轮训练中的泛化差异。

## 问题 4：kexue.fm 中的正则化方法（噪声、Dropout、对抗训练、梯度惩罚、Flooding、权重平均）哪些可迁移？

### Takeaway
苏剑林的统一观点是：输入噪声、Dropout、对抗训练、Flooding 都近似等价于某种梯度惩罚，都把模型推向更平坦的区域。对本目标最便宜且最有针对性的是：(1) 只作用于 Embedding 参数矩阵的 FGM 对抗扰动（需要 2 倍前向/反向，计算不对等）；(2) 以 unique 基线训练 loss 为水位的 Flooding（零额外计算）。R-Drop 和梯度 Dropout 证据较弱或成本较高。

### Cited Findings
- 提高泛化的两类手段：加噪声（输入高斯噪声、Dropout、对抗训练、数据扩增；加到输出 y 上等价于标签平滑）和加正则项（L1/L2、梯度惩罚）。输入加方差 σ² 的噪声，期望损失约为 l + ½σ²Δl（拉普拉斯项）；把目标换成 l(f(x+ε),f(x)) + l(f(x),y) 的上界后，正则项约为 ½σ²Σ_i λ_i(x)‖∇_x f_i(x)‖²，即梯度惩罚。随机噪声"不够特异性"，多数时候 x+ε 只是平凡样本，帮助有限。—— [泛化性乱弹：从随机噪声、梯度惩罚到虚拟对抗训练（2020-06-01）](https://kexue.fm/archives/7466)
- NLP 的对抗训练把扰动加到 Embedding 层。苏剑林的实现直接扰动 Embedding 参数矩阵：δ = ε·g/‖g‖（FGM），"得到的对抗样本的多样性会少一些（因为不同样本的同一个token共用了相同的扰动），但仍然能起到正则化的作用"；实验显示在很多任务中有效。同文讨论了对抗训练与梯度惩罚的等价性。—— [对抗训练浅谈：意义、方法和思考（附Keras实现）（2020-03-01）](https://kexue.fm/archives/7234)
- Flooding：L̃ = |L − b| + b，低于水位 b 时做梯度上升。苏剑林推导出：一步下降一步上升平均相当于以学习率 ε²/2 最小化 ‖∇L‖²，即"保证了损失函数足够小之后去最小化梯度范数"，推动参数往更平稳的区域走。他尝试从一开始就用不同学习率交替上升下降，"有些情况下会有轻微的提升"，"不如自己直接加梯度惩罚好"。—— [我们真的需要把训练集的损失降低到零吗？（2020-07-31）](https://kexue.fm/archives/7643)
- R-Drop：同一输入做两次 Dropout，加对称 KL 一致性项。苏剑林的解释是它降低 Dropout 的训练/预测不一致，使"关闭Dropout的效果等价于多Dropout模型融合"；他报告 R-Drop 可与对抗训练和梯度惩罚相比。—— [又是Dropout两次！这次它做到了有监督任务的SOTA（2021-07-01）](https://kexue.fm/archives/8496)
- ChildTuning-F 即梯度 Dropout（g ← g⊗M/p）。苏剑林指出：在带动量的优化器下，梯度为 0 不代表更新为 0，所以梯度 Dropout 达不到"每步只更新子网络"的目的，应该对更新量 Δθ 做 Dropout。—— [ChildTuning：试试把Dropout加到梯度上去？（2021-11-22）](https://kexue.fm/archives/8764)
- 权重平均与学习率衰减可以从理论上互相折算；等权平均效果不如滑动平均；Schedule-Free 仍需 Warmup，无法彻底摆脱调度。—— [让炼丹更科学一些（七）：步长调度与权重平均（2026-07-06）](https://kexue.fm/archives/11804)

### Inferences
- 4a（可测试方案："以 unique 基线训练 loss 为水位的 Flooding"）：
  - 是什么：重复 run 中，把 batch 平均损失替换为 |L − b(t)| + b(t)，b(t) 取同一词表 unique-token 基线在同一步的训练 loss（已有日志，可平滑后插值）。
  - 为什么可能有用：重复 run 的训练 loss 低于 unique run，这一差值就是记忆。7643 证明低于水位后的交替更新等价于梯度范数惩罚。b(t) 是自动、逐词表的水位，不需要调参。对所有词表适用。
  - 怎么实现：loss 函数中一行；b(t) 作为查表数组传入。零额外计算。
  - 风险：(1) 用 batch 平均，梯度上升作用于 batch 内全部 token，包括没有被记忆的高频 token。(2) 逐 token Flooding 会伤害本来就应接近 0 损失的 token（单词后半段等），不建议逐 token。(3) unique 基线的训练 loss 本身是在"新数据"上算的，重复 run 的训练 loss 在第 1 遍时与它相同，从第 2 遍开始才低于它，所以前 1/8 训练中 Flooding 不触发，符合预期。(4) 这是"用目标对照组的曲线约束实验组"，写进论文时要说明不是泄漏测试集（只用训练 loss）。
- 4b（可测试方案："Embedding 矩阵上的 FGM，只扰动当前 batch 出现的行"）：
  - 是什么：按 7234 的做法，第一次前向/反向得到 Embedding 梯度 G；对每个出现的行加 δ_i = ε·G_i/‖G_i‖（逐行归一化，而不是苏剑林原实现的整体归一化）；第二次前向/反向用扰动后的 Embedding 计算损失并更新。
  - 为什么可能有用：扰动方向正是"最能增加当前上下文损失"的方向，比主人队列中的随机输入噪声更特异（7466 的论点）。逐行归一化让稀有行和高频行受同样大小的扰动。
  - 风险：计算量约 2 倍。目标要求"同计算量"，所以必须减半步数或只在部分步使用（例如每 4 步 1 次，计算 +25%），否则不公平。ε 需要扫。我建议排在零成本方案之后。
- 4c：主人现有的最佳方案（训练中以一定概率把稀有输入行替换为其 8K 片段行均值）在 7466 的框架里属于"结构化乘性/替换噪声"，与 Dropout 同类。由此可推出一个便宜的增强：R-Drop 式一致性项会使"替换"与"不替换"两种前向的输出分布一致（8496），但需要 2 倍计算；更便宜的版本是只对替换位置计算一个 stop-gradient 目标。我认为这不是首批实验。
- 4d：8764 的论点适用于输入 Embedding：若要"随机跳过稀有行的更新"，应在更新量上做 mask，而不是在梯度上，因为 Adam 动量会继续推动该行。这与 2b 的 Lazy Adam 是同一个实现点，可以合并为一个"稀有行更新 Dropout"变体：Lazy + 以概率 p 丢弃出现行的更新。
- 4e：11804 说权重平均主要替代学习率衰减。Marin speedrun 已有衰减阶段，所以 EMA 对重复代价的额外收益可能小。若要测，成本只是多存一份参数并在评测时用 EMA 权重。优先级低。

### Gaps
- kexue.fm 没有 SAM、z-loss、Label Smoothing 专文（检索"z-loss""Label Smoothing""SAM"无专门命中；Label Smoothing 只在 7466 中作为"输出加噪声"一句提到）。
- 所有正则化文章的实验都是分类或微调任务（IMDB、CLUE 等），没有 LM 预训练、更没有多轮预训练的实验。

## 问题 5：长尾分类损失（logit adjustment、focal、其他恰当评分规则）能否用于稀有输出行？

### Takeaway
最可迁移的是 logit adjustment：给 logits 加固定的 τ·log p(y)。在 LM 中它不改变模型族（只是加一个不训练的偏置），评测时照常使用，所以不会引入训练/评测不一致。苏剑林还证明交叉熵是唯一只依赖目标概率的恰当评分规则，其他恰当评分（Brier、Tsallis、球面）不改变最优解，但梯度性质不同；这一点说明替换损失不会在无限数据极限下偏离 bpb 目标，但没有证据说明它能减轻记忆。

### Cited Findings
- 长尾问题的三类方法：重采样、按类别频率重加权 loss、预测时调阈值。苏剑林提出让模型拟合互信息 log p(y|x)/p(y)，等价于 logit 上加 log p(y) 再 softmax，即 Google 的 logit adjustment loss；可加系数 τ，"一般情况下，τ=1 的效果就已经接近最优了"；若最后一层有 bias，可直接把 bias 初始化为 τ·log p(y)。—— [通过互信息思想来缓解类别不平衡问题（2020-07-19）](https://kexue.fm/archives/7615)
- 调节样本权重与 Focal、Dice、Logit Adjustment 等"魔改 loss"之间的联系梳理。—— [再谈类别不平衡问题：调节权重与魔改Loss的对比联系（2020-08-31）](https://kexue.fm/archives/7708)
- 交叉熵对低概率样本给出极大损失，导致过度自信、过拟合脏数据。TVD 论文给出 −log[γ + (1−γ)p]/(1−γ)，γ=0 为交叉熵，γ=1 为 −p；论文在语言模型任务取 γ=1e-7；从零训练应选接近 0 的 γ。—— [缓解交叉熵过度自信的一个简明方案（2023-03-14）](https://kexue.fm/archives/9526)
- LM 损失必须对目标分布线性（可采样估计），因此只能是恰当评分规则；任意凹函数 H(p) 给出一个评分 S(q,i)；若要求 S 只依赖 q_i，则只有交叉熵；两个评分的线性插值仍是评分。Brier 评分在"自信地错误"时梯度消失，学习效率低，但抗噪声；苏剑林建议交叉熵作为主损失，平方损失"后期可以尝试"。—— [除了交叉熵，LM Loss还有什么选择？（2026-08-09）](https://kexue.fm/archives/11854)

### Inferences
- 5a（可测试方案："lm_head 加固定的 log-unigram 偏置"）：
  - 是什么：logits_i ← logits_i + τ·log p̂(i)，p̂ 为训练子集（1/8 子集）上该词表的平滑 unigram 频率，不训练；τ ∈ {0.5, 1}。
  - 为什么可能有用：稀有输出行目前要同时学"低先验"和"条件信息"。偏置把先验拿走，稀有行只需学互信息部分（7615 的论点）。在重复数据下，输出侧的代价有一部分可能来自稀有行把少量上下文过度拟合进"先验方向"。所有词表都适用；256 字节词表几乎无变化，可作对照。
  - 怎么实现：Qwen3 的 lm_head 无 bias，在 logits 计算后加一个常数向量即可。评测时同样加（模型族不变，bpb 计算合法）。
  - 风险：(1) 低：它是固定重参数化，最坏情况模型学会抵消它。(2) p̂ 只用训练子集计算，避免使用评测集信息。(3) 它能否减少"记忆"没有任何文章证据，只能减少"先验学习"的负担。
- 5b：9526 的 γ-CE 降低低概率目标的梯度，对象是"难/脏样本"，不是被记忆的样本（被记忆的样本训练概率已经高，CE 梯度本来就小）。它改变了训练目标，bpb 评测用交叉熵，所以可能直接损害 bpb。优先级低。
- 5c：11854 提示，若想在重复后期混入一个"抗过度自信"的损失，应混入恰当评分（如 Tsallis α 略大于 1），不改变无限数据下的最优解。但没有任何证据它减轻记忆。优先级低。
- 5d：按频率重加权损失（7708 的第一类方法）会让稀有 token 损失权重变大，方向与本目标相反（会加重稀有 token 的记忆）；反过来降低稀有目标权重会直接损害稀有 token 的 bpb。不建议。

### Gaps
- kexue.fm 没有关于 softmax bottleneck、LM 中 sampled softmax 的文章（sampled softmax 只在 word2vec 实现文 4402 中出现）。
- 没有文章讨论 logit adjustment 用于生成式 LM 的效果。

## 问题 6：数据层面——随机分词（Subword Regularization、BPE-Dropout）能否作为每遍不同的数据扩增？

### Takeaway
这是 kexue.fm 中与"现有最佳方案"最接近的思路。苏剑林明确说训练时用带随机性的分词，使"白云机场"有时作为一个词、有时作为"白云/机场"出现，"甚至能增强泛化能力"。他给出 BytePiece 的 Viterbi Sampling（Unigram 模型）并证明修正版是完美采样；BPE 对应的方法是 BPE-Dropout。对本目标，它是一种对每一遍生成不同 token 序列的数据扩增，同时作用于输入行和输出行。

### Cited Findings
- 大词表 LM 在续写时有"token healing"问题（"import numpy as np"整体成一个 token 后，输入"import numpy"无法续写" as np"）。苏剑林提到可以"在训练阶段就使用带有随机性的tokenize算法，这种情况下'白云机场'可能作为一个词出现，也可能作为'白云/机场'出现，此时分词结果不至于严重影响后续效果，甚至能增强泛化能力"，引用 Subword Regularization（1804.10959）。—— [9762](https://kexue.fm/archives/9762)
- Subword Regularization 的做法：取 n-best 切分，按 P(w)^α 归一化采样。BytePiece 0.4.0 起的 Viterbi Sampling 把 Viterbi 中的 `if score > routes[e][0]` 换成概率接受；速度对比：SP-Unigram 随机分词降到确定性的不到 1/4（5.65M→1.28M bytes/s），BytePiece 只降约 30%（1.95M→1.36M），SP-BPE 1.36M→1.25M。BPE 模型的随机分词叫 BPE-Dropout（1910.13267）。—— [随机分词浅探：从Viterbi Decoding到Viterbi Sampling（2023-09-16）](https://kexue.fm/archives/9768)
- 读者指出旧版 Viterbi Sampling 的多次二选一会稀释早到方案的概率。修正版缓存累积权重 Z_i = Z_{i−1} + e^(αs_i)，以 e^(αs_i)/Z_i 接受新方案（水塘采样），可证明是与 Subword Regularization 等价的完美采样；α→∞ 退化为 Viterbi Decoding；实现在 bytepiece>=0.5.0。—— [随机分词再探：从Viterbi Sampling到完美采样算法（2023-10-16）](https://kexue.fm/archives/9811)

### Inferences
- 6a（可测试方案："词表截断 Dropout"，即主人现有方案的序列级版本）：
  - 是什么：8K/16K/32K/64K 词表是 128K 的前缀截断，所以截断词表的 token 都在 128K 词表内。对每一遍、每一次稀有 token（rank > 8K）的出现，以概率 p 把它替换为该 token 字符串在 8K 截断词表下的切分，输入位置和目标位置同时替换。
  - 为什么可能有用：(1) 每遍得到不同的 token 序列，降低重复度（9762 所说的泛化收益）。(2) 主人现有方案只替换输入行；本方案同时替换目标，所以也作用于稀有输出行，而已知代价也在输出行上。(3) 输出侧把一部分概率质量交给更短的片段路径，减少稀有输出行每遍从同一上下文拿到的梯度。(4) 对每个词表都可定义（128K→8K，64K→8K，……）；256 字节词表可以把字节组合视为不可再分，作为负对照。
  - 怎么实现：不需要重新跑分词器。预先计算 token id → 8K 片段 id 序列的映射表；在 data loader 中按 (token, pass, seed) 哈希决定是否替换；替换后序列变长，需要截断或重新打包到固定 seq_len。评测保持确定性分词。
  - 风险：(1) 训练/评测分布不一致：模型把一部分概率分给非规范切分，bpb 按规范切分计算时这部分质量浪费。p 要小（0.05–0.2），并可以只在第 2–8 遍使用。(2) 每遍 token 数变化，"同计算量"的对比要按 token 计还是按 byte 计需要事先定好。(3) 序列打包改变，需要确认 Marin 的数据管道能做在线变换。
- 6b（完整版：标准 BPE-Dropout）：HF tokenizers 的 BPE 模型支持 `dropout` 参数。可对 1/8 子集离线生成 8 份不同的随机分词缓存（每遍一份）。比 6a 更"真实"，但需要重新分词 8 次，且所有合并都可能被丢弃，扰动更广。256 字节词表无合并可丢，同样作为对照。风险与 6a 相同，额外的离线分词成本在 CPU 上。
- 6c：Unigram/BytePiece 的 Viterbi Sampling 只适用于 Unigram 词表；Marin 的词表是 BPE，所以直接相关的是 BPE-Dropout，而不是 Viterbi Sampling。

### Gaps
- kexue.fm 没有报告随机分词在 LLM 预训练（尤其是多轮）上的实测 bpb 或 perplexity；"能增强泛化能力"是引用 NMT 论文的转述。
- 没有文章讨论随机分词与 bpb 评测之间的不一致代价。

## 问题 7：按"便宜、8 GPU·h 内可测、对所有词表适用"排序，哪些 kexue.fm 思路最值得先测？

### Takeaway
首批建议 3 个零额外计算的实验：Lazy Adam 只用于输入 Embedding（2b）、输入 Embedding 加记忆周期为一轮的 WD（1b）、lm_head 加固定 log-unigram 偏置（5a）。第二批：以 unique 基线训练 loss 为水位的 Flooding（4a）和"词表截断 Dropout"（6a）。FGM（4b）和部分 Tie（2d）成本或风险较高，放在最后。

### Cited Findings
- 动量优化器对稀有 Embedding 的过度更新与 Lazy 对策 —— [6869](https://kexue.fm/archives/6869)、[9736](https://kexue.fm/archives/9736)
- 多轮训练时让 1/(λη) 正比于单轮步数 —— [11459](https://kexue.fm/archives/11459)
- logit adjustment，τ=1 接近最优 —— [7615](https://kexue.fm/archives/7615)
- Flooding 等价于低于水位后的梯度范数惩罚 —— [7643](https://kexue.fm/archives/7643)
- 训练时随机分词可增强泛化 —— [9762](https://kexue.fm/archives/9762)、[9768](https://kexue.fm/archives/9768)、[9811](https://kexue.fm/archives/9811)
- Embedding 参数矩阵上的 FGM —— [7234](https://kexue.fm/archives/7234)

### Inferences
建议的执行顺序（每项先在 128K 和 8K 两个词表上测；有效再扩到全部 6 个词表，并配对跑 unique 基线）：
1. 2b Lazy Adam（输入 Embedding）。代价：约 10 行代码，0 额外计算。预测：128K 的 cost 下降幅度大于 8K；256 字节几乎不变。若 128K 与 8K 同幅下降，则说明作用机制不是稀有行。另做两个变体：苏剑林版（m、v 照常衰减）和标准版（m、v 冻结）。
2. 1b 输入 Embedding WD，记忆周期 0.5、1、2 轮。代价：1 行代码，0 额外计算。可与 1 组合（Lazy 的 WD 只对出现行生效时，记忆周期以"出现次数"计，含义不同，需要单独标注）。
3. 5a 固定 log-unigram 偏置，τ = 0.5、1。代价：几行代码，0 额外计算。预测：若输出侧代价主要来自"先验学习"，稀有输出行代价下降；否则无变化。
4. 4a Flooding，水位为 unique 基线训练 loss 曲线。代价：1 行代码加一个查表数组，0 额外计算。
5. 6a 词表截断 Dropout，p = 0.1，只在第 2–8 遍。代价：data loader 改动，0 额外 GPU 计算，但 token 数变化，需定义计算对等。
6. 4b FGM（逐行归一化）每 4 步 1 次，计算 +25%，需减步数保持对等。
7. 2d 部分 Tie，风险最高，最后考虑。

与已排队实验的关系：残差 dropout 和输入噪声属于 7466 的"随机噪声"类，苏剑林认为它们"不够特异性"；1、2、3 作用于不同机制（优化器动量、记忆周期、输出先验），与已排队实验互不重叠，可以组合。

### Gaps
- 以上排序完全是我的推断。kexue.fm 中没有任何一项在多轮 LLM 预训练上被验证过。
- 2a 的 13 倍放大用的是 `muonh.py` 默认 β1=0.9、β2=0.95；speedrun 实际配置未核对。
- 无法从 kexue.fm 判断这些方法对 MuonH（超球面）主干的交互；苏剑林的流形系列只给优化方向，不给泛化结论。
